Linux source facts already used:
- Linux `fs/quota/quota.c` copies `Q_XQUOTARM` flags from userspace before returning `-ENOSYS` if `rm_xquota` is absent.
- Linux `do_quotactl` checks `!sb->s_qcop` before type support/permission/switch and returns `-ENOSYS`.
- `quotactl(special == NULL)` allows only `Q_SYNC`; other commands return `-ENODEV`.
- `quotactl_fd` validates fd first, then qtype, then mount write access for write commands.
- Linux treats classic `Q_GETQUOTA`/`Q_GETNEXTQUOTA` as write-blocking, but XFS `Q_XGETQUOTA`/`Q_XGETNEXTQUOTA` as read-only.
- Linux ext4 uses separate quotactl operation sets for regular quota files versus quota-feature system files; system-file quotaon/off toggles enforcement, not accounting teardown.
- Linux classic `Q_GETINFO`/`Q_SETINFO` copies `struct if_dqinfo` (`bgrace`, `igrace`, `flags`, `valid`), not XFS realtime/warning fields.
- Linux classic `if_dqinfo.dqi_valid` is only `IIF_BGRACE|IIF_IGRACE|IIF_FLAGS`; RT/warning info bits are XFS-only.
- Linux `Q_XGETQSTAT`/`Q_XGETQSTATV` return `ENOSYS` when computed `qs_flags` is zero before quota-file stats can make the call succeed.
- Linux `Q_XGETQSTAT`/`Q_XGETQSTATV` use filesystem `s_qcop->get_state`; generic VFS now exposes `SuperOps::quota_get_state`/`QuotaState`, with a default dquot-ops implementation, and XFS qstat maps that state instead of reading every field directly from `s_dquot`.
- Linux `fs/quota/quota.c` still returns `EROFS` for targeted `Q_XQUOTASYNC` on read-only superblocks before the no-op success path.
- Linux `sys_quotactl(Q_QUOTAON)` resolves the quota-file path after null-special/type checks but before resolving the block-device `special`; the stored bad-`addr` error is returned only for visible quota-file `quota_on`, while system-file `quota_enable` can ignore it.
- Linux `Q_XSETQLIM` id-0 timer/warning updates use `copy_qcinfo_from_xfs_dqblk` low 32-bit timer values; `FS_DQ_BIGTIME` high-byte decoding applies to per-id quota records, not quota-info grace fields.
- Linux `Q_XSETQLIM` id-0 timer/warning updates call filesystem `s_qcop->set_info` before `set_dqblk`; local `SuperOps::quota_set_info_xfs` now mirrors that filesystem-owned info boundary.
- Linux `quotactl_fd(Q_QUOTAON)` passes an invalid path to classic quota-on; system-file filesystems must still take the `quota_enable` hook, while visible quota-file `quota_on` returns that path error.
- Linux `quotactl_fd` relies on `mnt_want_write` for mount write admission and freeze waiting, locks `s_umount`, calls `do_quotactl`, unlocks, then `mnt_drop_write`; local `quotactl_fd_file` uses explicit `sb_start_write` because local `mnt_want_write` is mount-writer-only.
- Linux block-target `quotactl_block` waits for thaw before read-only rejection; local B804 keeps `wait_until_thawed()` writer-free, then rejects write-class block-target commands with `EROFS` before current-task/usercopy/backend hooks.
