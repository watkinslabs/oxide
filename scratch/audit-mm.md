# MM subsystem audit — oxide vs Linux

DRAFT 2026-07-27. Dep:11,12,31,53. Linux source of truth: `/home/nd/oxide/linux-master` (v7.2.0-rc4).
Scope: `crates/kernel/mm-vmm`, `crates/kernel/mm-pmm`, `crates/shared/{kalloc,slab}`, mm-owned
surfaces in `crates/kernel/{exec,syscalls,procfs,vfs,ext4,cgroup,sched}`.
Sibling audits merge on the shared 8-column schema. Severity vocabulary: `BLOCKER`,
`SECURITY`, `CORRECTNESS`, `PERF`, `ABSENT-OK`.

Method: every row read on both sides. `ABSENT (grep: …)` means the grep is the evidence.
A function that exists but has no production caller is recorded as a gap, not as present.

## Ordering

Ranked by impact, with the cheap-and-decisive items pulled forward.

1. **`evict_foreign_pages_in_range` frees pages with no TLB flush (§8, BLOCKER).** A cross-process
   use-after-free reachable from `process_madvise`/`process_mrelease`, justified in-file by an
   "oxide is UP" claim that is false. Smallest fix, worst consequence — do this first.
2. **No global OOM killer (§4, BLOCKER).** Without a cgroup limit — the normal desktop case —
   exhaustion never kills anything; allocations just fail and the faulting process takes a
   SIGSEGV. Needs `select_bad_process` + `oom_kill_process` + `panic_on_oom`; the badness
   scorer already exists (fix its PSS-vs-RSS unit at the same time).
3. **No dirty-page throttling and no background writeback (§5, BLOCKER).** Unbounded dirty
   growth against a shrinker that refuses dirty pages is a direct route to OOM under any
   sustained writer. Pairs with #2.
4. **Missing PTE A/D harvest (§8) → dead LRU aging and dirty tracking (§4, §5).** One root
   cause under four separate CORRECTNESS rows: reclaim picks victims blind, `mkclean` cannot
   exist, and shared-file writeback loses the second write. `age_anon`/`mark_lru_referenced`
   are already written and merely uncalled.
5. **W^X, SMEP/SMAP/PAN, KPTI (§8, five SECURITY rows).** The kernel image is writable, the
   whole direct map is executable on both arches, and the kernel may freely execute and
   dereference user memory. Independent of mm's own correctness and mostly boot-time
   page-attribute + CR4/SCTLR work.
6. **userfaultfd: unprivileged, ungated, and able to install RW pages at any VA with no VMA
   (§7, two SECURITY + two CORRECTNESS rows).** The 24-vs-16-byte `uffdio_api` struct and the
   off-by-one range-ioctl bitmap are near-trivial and should ride along.
7. **ASLR — DONE (F771).** All six components land in one PR: PIE load bias, interpreter
   base, `mmap_base`, stack top, `brk`, vDSO. Two of the six are "derived" in Linux itself
   rather than independently drawn — the interpreter and the vDSO are both placed by
   `get_unmapped_area` off the randomised `mmap_base` (`fs/binfmt_elf.c:686-689`,
   `arch/x86/entry/vdso/vma.c:174`), so implementing them means routing them through the
   arena, not adding a draw. The audit's original claim that `map_vdso_randomized()` takes
   its own random slot was reading an older kernel; no such function exists in v7.2.0-rc4 on
   either arch. Policy and entropy budgets live in one crate (`crates/kernel/aslr`), the
   sysctl binds to it, and `AT_RANDOM` (F768) plus PID 1's own `random16` (F771) both come
   from `crng`. `randomize_va_space` reports `2` and `2` is now true.
8. **Unenforced mm limits (§2, four SECURITY rows).** `RLIMIT_AS`, `max_map_count`,
   `mmap_min_addr`, `mlockall`/`MAP_LOCKED` admission, and the stack guard gap. Each is a
   single check at a known call site; together they are the cheapest SECURITY yield in the
   audit.
9. **`/proc` mm surfaces lie (§3, CORRECTNESS).** `VmRSS` = virtual size and `/proc/*/maps`
   with no pathnames. The data already exists (`range_memory_stats` is used by smaps), so
   these are wiring bugs, and they block every memory-profiling and crash-analysis tool.
10. **aarch64 barrier ordering — TLBI-before-DSB and unbarriered table publication (§8,
    CORRECTNESS).** Architecturally incorrect on every ARM PTE mutation. Rare in practice on
    a 2-CPU TCG/KVM guest, which is exactly why it will be found late and expensively.
11. **Truncate/hole-punch/`fadvise(DONTNEED)` do not unmap live PTEs (§5, CORRECTNESS).**
    `FileRmap::walk_page` already exists and is used by tmpfs; the ext4 and setattr paths
    simply never call it.
12. **mremap byte-copies instead of moving page tables, and never grows in place (§7).**
    Breaks large sparse arenas (jemalloc, Go, JVM) that Linux handles trivially.
13. **Allocator scalability (§6, PERF).** One global-locked first-fit hole list for every
    kernel allocation, a complete slab allocator with zero consumers, no per-CPU page lists,
    no vmalloc, no DMA zone. Structural, and worth its own phase.
14. Remaining PERF rows: readahead that computes a window and issues no I/O, per-process vDSO
    copies, no swap cache, no compaction, no PCID/ASID.

## What I could not determine

- **Whether the live-gnome image activates any swap area at boot.** No fstab or zram-generator
  config was found under `userspace/`; only `userspace/swapfile_probe/` exercises `swapon`
  explicitly. If no swap is active at runtime, every anon-reclaim path in §4 is a no-op and the
  severity of the anon-only-reclaim rows rises.
- **Whether the vendored systemd is built with `-Doomd=true` and whether `systemd-oomd.service`
  is enabled.** That decides whether the missing cgroup `memory.pressure` is a boot-visible
  failure or a silent capability loss.
- **Whether `sync::Spinlock::lock` masks IRQs.** If it does, `flush_reclaim_mapping()` called
  inside the `lock_page_table()` scope in `pageout.rs` is a sender↔waiter shootdown deadlock
  resolved only by the 1e9-spin cap. Settling this needs a read of `crates/shared/sync` that
  no lane completed.
- **Whether any CPU actually reaches the `[TLB-MISSED-FLUSH]` cap in practice** — requires a
  boot, which this lane is barred from.
- **Whether the uffd `install_pages` frame is ever reclaim-visible.** It comes from
  `alloc_one_frame` so teardown releases it, but it is never admitted to an LRU, never charged,
  and gets no rmap edge; whether reclaim skips it or misclassifies it needs the PMM harness.
- **Whether the residual `block::PageCache` can hold file data concurrently with
  `Ext4FrameStore`** in the default build — the `#[cfg(not(ext4-frame-cache))]` arms could not be
  proven dead.
- **Whether `MAP_SHARED` dirty data survives process exit before an explicit sync.**
  `Drop for Ext4FrameStore` flushes, but the store's lifetime is the inode's, not the mapping's;
  whether an icache eviction can occur while a dirty shared mapping is live was not traced.
- **Reachability of the device-VMA COW-copy arm (§7).** The absence of a guard in
  `handle_write_protection` is confirmed; that a `PhysRange` PTE can actually be present-and-RO
  at fault time was not proven end to end.
- **Whether `mremap`'s user-VA byte loop would fault under SMAP** — moot today since SMAP is
  never enabled (§8), but it becomes a hard failure the moment SMAP lands.

Out of scope but observed while reading: `/proc/<pid>/status` hard-codes
`Uid:\t0\t0\t0\t0` and `Gid:` likewise (`crates/kernel/procfs/src/live/self_files.rs:164`),
independent of the task's real credentials. That belongs to the procfs/creds lane, not mm.
