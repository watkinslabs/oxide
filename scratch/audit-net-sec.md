## Ordering

222 findings: 16 BLOCKER, 39 SECURITY, 102 CORRECTNESS, 14 PERF, 51 ABSENT-OK. Ordered by impact,
grouped so each group is one lane.

1. **The missing-`poll_subs` defect — 5 BLOCKER rows, one root cause.** tty and pty inodes (§13),
   ext4-backed FIFOs (§12) and mqueue fds (§11) are all built without `.poll_subs(...)`, so
   `File::poll_subscribers()` returns `None`, `sys_poll` parks with `park_dl = 0` and no wake source,
   and `epoll_ctl(ADD)` produces an epitem with no source callback. Three lanes found this
   independently in three subsystems. It is a one-line-per-inode fix plus a notify at each event
   site, and it is the highest-value item in this audit. Terminal readiness currently works only by
   accident of epoll's O(N) `rescan_levels` fallback (§2) — which is also why the bug has stayed
   hidden.
2. **Write-readiness never de-asserts — 2 BLOCKER rows.** Every AF_UNIX and TCP poll mask sets
   `POLL_OUT` unconditionally (§1, §4) while the send paths genuinely enforce capacity and return
   EAGAIN. A non-blocking poll-driven writer against a slow reader spins at 100 % CPU forever, on the
   exact path dbus-broker, systemd, Wayland compositors and Xwayland use. The drain-side edge already
   fires; only the level predicate is missing.
3. ~~**The exec transition has no floor.**~~ CLOSED by `B1464-exec-privilege-transition`: setuid/setgid,
   `MAY_EXEC`, `AT_SECURE`, `MNT_NOSUID`, `MNT_NOEXEC`, `MNT_NODEV`, ambient caps, `SECBIT_NOROOT`,
   the `LSM_UNSAFE_*` downgrade, `PER_CLEAR_ON_SETID` and dumpability all landed in ONE PR, for the
   reason the original finding gave — shipping setuid *before* secure-exec would create an
   escalation primitive that does not exist today.
4. **tty and VT privilege gates are absent — 6 SECURITY rows, one lane (§13).** `TIOCSCTTY`,
   `TIOCSPGRP`/`TIOCGPGRP`, `TIOCLINUX` (a working TIOCSTI-equivalent paste into the foreground root
   console), the whole `vt_ioctl` surface, `KDSKBMODE` `K_OFF` being stored and never read (so
   graphical-session keystrokes are also fed to the text console behind it), and `vhangup(2)` not
   revoking. Each is a missing check on an existing mechanism.
5. **`/proc/PID/status` reports every process as uid 0 with the full capability set** (§8), as
   literal constants, while the real credentials in `sched` are correct. polkit, `ps` and every
   userspace authorisation check reads this. Pair it with the two other lying sysctls —
   `kernel.yama.ptrace_scope` and `fs.protected_symlinks` both claim protections that have no reader.
6. **inotify cannot watch a directory** (§12): no parent walk, so no MODIFY/ACCESS/OPEN/CLOSE for
   files inside a watched directory, and no event ever carries a filename. Two BLOCKER rows that
   together make gio `GFileMonitor` and systemd `.path` units non-functional.
7. **pty slave last close never hangs up the master** (§13) — the master spins forever instead of
   getting EIO, so ssh, tmux, `script` and terminal emulators hang at session end. Adjacent:
   `disassociate_ctty(1)` absent and `ctty` on the task rather than the thread group (both standing
   ledger items, both **confirmed**); the second unblocks the first.
8. **Firewalling is structurally unsound** (§5): no conntrack and no NAT at all, and unknown nft
   expressions are *silently skipped* so a rule loads with its match half removed and its verdict half
   intact — `ct state established,related accept` degrades to an unconditional accept. Fix the silent
   skip first; it is small, and until it lands every added expression changes behaviour invisibly.
9. **Entropy** (§10): CRNG readiness is fabricated (`getrandom` can never block, `GRND_NONBLOCK` can
   never return EAGAIN) and on aarch64 without FEAT_RNG the pool is declared seeded from a single
   `CNTVCT_EL0` read. The ChaCha20 construction is correct; the seed and the readiness signal are not.
10. **Two clean memory-safety-adjacent bugs, both cheap.** io_uring's `IORING_REGISTER_EVENTFD`
    accepts any fd and open-codes `inode().write`, bypassing `f_mode` — the kernel will write into an
    `O_RDONLY` file (§12). virtio's `program_queue` allocates one 4 KiB frame regardless of
    `queue_size`, so a device advertising >256 descriptors gets DMA writes past the frame (§9).
11. **Display and boot-critical drivers.** `DRM_CAP_PRIME == 0` blocks Mesa/GBM and therefore mutter
    (§10); the 8-buffer virtio-net RX pool is the best candidate for the intermittent NM bring-up
    failure and is provable in a hosted harness; the aarch64 wall clock is never seeded from an RTC,
    which breaks TLS and PAM on that arch and violates the lockstep rule.
12. **Accounting and lifetime leaks**, low blast radius but unbounded: SysV shm attach counts leak on
    `munmap`/exit; every pty and every timerfd leaks for the life of the boot; Landlock rulesets are
    never freed; the N_TTY read queue is uncapped (§12, §13).
13. **PERF, once correctness lands**: epoll's O(N_watched) rescan per wakeup, per-packet nftables
    ruleset re-parse, the pty yield-spin, TCP's never-sampled RTT (a fixed 1 s RTO and `tcpi_rtt` = 0),
    polled NVMe/AHCI, and virtio's unnegotiated `EVENT_IDX`/`INDIRECT_DESC`.

Two cross-cutting observations worth acting on before the individual fixes. First, the recurring
shape in this audit is **a correct mechanism that nothing calls**: `update_rtt`, `TtyStruct`'s
`PollSubscribers`, `static_console::poll_subscribers`, `encode_get_edid`,
`register_family`, `virtio::queue::VirtQueue`, `sigpend::all_pending`. Grepping for
production-callerless `pub fn` in these crates would likely find more. Second, several rows are
**split sources of truth** in the sense `CLAUDE.md` forbids — sysfs link state vs rtnetlink, the shm
id space vs `sysv::ids`, the pty ldisc vs `NTty`, the mqueue model vs the mounted `PseudoFs`, the
global `UNIX_REGISTRY` vs the per-netns one — and each will regrow if only one side is fixed.

## What I could not determine

Stated plainly — these were not verified by reading, and no row above depends on them.

- **AF_VSOCK depth.** Structural scan only: `vsock/conn.rs` has a real STREAM state machine with credit accounting (`buf_alloc`/`fwd_cnt` folding, `credit_update_pending`), `SOCK_SEQPACKET` record framing, and canonical `(CID, port)` reservation with ephemeral selection; there is a Linux-differential test file. No gap found, but I did not diff it against `net/vmw_vsock/` message by message — lowest-value item in my scope per the brief.
- **IPv6 SLAAC/RA/DAD correctness.** The modules exist (`ndp.rs`, `stack_slaac_tests.rs`, `icmpv6.rs`, `ipv6_ext.rs`, `ipv6_reasm.rs`) with tests. I confirmed presence, not correctness.
- **Routing/FIB and neighbour NUD state machine.** `route.rs`, `route6.rs`, `policy_rule.rs`, `arp.rs`, `ndp.rs`, `stack/arp_neighbor.rs` all exist and rtnetlink drives them. Presence confirmed; longest-prefix-match, source-address selection (RFC6724), and the six-state NUD machine were not verified.
- **Whether the missing `MAY_WRITE` check on AF_UNIX connect is exploitable in the shipped image.** It depends on the mode of `/run/systemd/private` and friends in this rootfs, which I could not check without booting.
- **The full 281-hook LSM surface.** The desktop-relevant hooks were sampled rather than walked exhaustively; the "no chokepoint exists" conclusion is structural and solid, the per-hook inventory is not.
- **Whether `path_lookup_at_root_cred` uses fsuid/fsgid.** Linux resolves paths with `fsuid`/`fsgid`, not `euid`. `crates/kernel/syscalls/src/pathresolve/cred.rs` was not read in full.
- **Whether QEMU honours `VIRTIO_BLK_T_FLUSH` when `F_FLUSH` was never acked.** The oxide-side defect (issuing an unnegotiated command) is certain from the source; the size of the real data-loss window depends on backend behaviour that needs a run to establish.
- **Whether the 8-buffer RX pool is *the* cause of the intermittent virtio-net bring-up failure or one of several.** It is the strongest mechanism found and is provable in a hosted harness (drive `rx_poll_for` with >8 queued used entries) — that harness is the recommended next step, not a boot.
- **Whether Mesa can drive `gbm_create_device` on a card fd with dumb buffers and `DRM_CAP_PRIME == 0`.** `kms_swrast` is the only candidate path and could not be confirmed without running it.
- **Whether any PCI-to-PCI bridge exists in the default QEMU q35/virt topologies**, which decides whether the bridge config-clobber row fires today or is purely latent.
- **Real MSI-X delivery on aarch64 through the ITS path.** The code is complete and plausible; the `MSI_FIRES` counters are only readable from a live boot.
- **Whether the production fault handler recovers from a kernel-mode fault at an unmapped user VA.** This bounds the *consequence* of the mqueue user-buffer row (§11) — not its existence. If it does not recover, that row is a trivially reachable unprivileged kernel fault.
- **Whether oxide's netlink `recvfrom` returns the `mq_notify` 32-byte cookie unframed**, as glibc's SIGEV_THREAD helper thread expects.
- **Whether epoll consumes `FileOps::poll_deadline_ns`** the same way `sys_poll` does.
- **Whether the pipe/FIFO lost-wakeup windows actually strand a task under the live scheduler.** The window is visible in the source; it was not demonstrated.
- **`IN_EXCL_UNLINK` / `IN_UNMOUNT` fire sites**, and whether any pts open path bypasses the DAC check at `open_common.rs:164`.
- **SysV blocking paths have never executed.** `semop`/`msgsnd`/`msgrcv` sleep paths and `shmdt`'s address-space half read correct but are unproven: hosted builds have no `mm` and `basic.target` does not exercise them. This is the standing `A4` ledger item; `userspace/wait_diff/` is the harness that could execute them.
