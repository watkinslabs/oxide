# Boot performance history

This file is append-only. Each row is a fresh `make perf-report SMP=1` run
using the same GNOME image profile and the host baseline generated by
`tools/perf/linux-baseline.c`. The syscall values are on-CPU kernel time; the
block values are the measured device totals. Keep the generated
`scratch/perf-report.md` is a generated working artifact; record material
changes here so later lanes can compare against the same workload even after
that artifact is regenerated.

| lane / commit | syscalls | CPU ms | avg ns | munmap ns | sendmsg ns | newfstatat ns | block read ms | block write ms | notes |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---|
| B2699 baseline / `5ff9c0e11` | 1,170,786 | 7,318 | 6,250 | 71,407 | 28,235 | 22,519 | 338 | 2,967 | queue-depth investigation baseline |
| B2708 / `569260958` | 1,365,729 | 7,612 | 5,574 | 21,764 | 35,112 | 21,764 | 254 | 3,185 | DMA ordering + stat-walk lane; no measured stat win |
| B2709 / `eac588295` | 1,366,469 | 6,518 | 4,770 | 21,426 | 27,372 | 19,912 | 248 | 2,551 | combined page-table lookup/teardown |

The B2709 `munmap` result is a material improvement over B2699: 71,407 ns
to 21,426 ns (about 70% lower), and 52x to 16x the host baseline. The B2708
row is retained even though its `newfstatat` change stayed within harness
noise. Run-to-run variance remains substantial; a row should be called a
win only when it moves by more than the report's documented noise bar.
