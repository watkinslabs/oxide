# B1721 — devpts mount options

| Status | Class | Sev | Issue | Evidence | Owner |
|---|---|---|---|---|---|
| FIXED (this PR) | MISSING | high | **devpts discarded every mount option, on every boot.** Its registration used `FsType::new` (no parameter table) and its constructor took `_` for the data string, so `-o gid=5,mode=620,ptmxmode=000` — which systemd passes at every single boot — was dropped whole. Slave nodes were born `0o620` from a hardcode that happened to match the requested mode, so the value looked right while nothing read the option; a mount asking for anything else got `0o620` regardless. Ownership was never set at all, and `/dev/pts/ptmx` stayed `0o666` where `ptmxmode=000` asked for `0`. All six reference options are now declared and enforced: `uid=`/`gid=`/`mode=` stamp each slave, `ptmxmode=` the instance `ptmx`, `max=` bounds index allocation, `newinstance` is the reference's own accepted no-op. | `crates/kernel/devpts/src/mount_opts.rs` (ungated policy, 13 tests), `inodes.rs` (4 stamping tests), `fs.rs`, `registry.rs`. Guest, both arches: `/proc/mounts` now reports `gid=5,mode=620,ptmxmode=000` (it reported nothing before) and `/dev/pts/ptmx` is mode `0` (was `0666`). Positive control: restoring the hardcode turns the 3 stamping tests RED. | B1721 |
| FIXED (this PR) | DEFECT | med | **`mode=`/`ptmxmode=` are OCTAL and were never parsed at all.** `fsparam_u32oct`: `mode=620` means `0o620`. Anything reading that value as decimal gets `0o1154` — the set-user-ID bit plus a wrong permission set — on every pty slave. Parsed as octal here, masked with `S_IALLUGO`, and rendered back as `%03o` so a displayed `mode=020` reads back as the same value rather than as `mode=20`. | `mount_opts::tests::the_option_string_every_boot_passes_is_parsed_the_way_the_reference_reads_it`, `a_mode_cannot_smuggle_a_file_type_bit_past_the_mask`, `the_shown_options_round_trip`. | B1721 |
| OPEN | DEFECT | med | **`DevptsFs` is a process-wide singleton, so `newinstance` cannot mean anything and two devpts mounts share one pty namespace and one set of options.** The reference gives each mount its own `pts_fs_info` (its own `allocated_ptys` ida, its own `mount_opts`, its own root); here `devpts_fs()` returns one instance to every mount, so a second `mount -t devpts` with different options silently retunes the first, and container-style private `/dev/pts` instances do not exist. This is the same shape as the procfs singleton B1719 removed, and it wants the same fix: build the instance per mount and let the `/dev/ptmx` open path resolve the instance from the ptmx node it was opened through. `newinstance` is accepted because the reference accepts it as a no-op — that part is conformant — but the multi-instance capability behind it is absent. | `crates/kernel/devpts/src/fs.rs` `static DEVPTS_FS` + `devpts_fs()`; its own doc comment records the single global pty namespace as a residual. | unowned |
| OPEN | DEFECT | low | **`max=` is bounded against a monotonic total, not a live count.** `pair::next_index()` is a never-decrementing `AtomicU32`, so `max=N` refuses allocation once N ptys have EVER been created rather than once N are live. The reference frees the index back to an ida on pty teardown, so a long-lived system reuses indices and `max=` bounds concurrency. Enforcing the ceiling against the counter we have is strictly closer to the reference than ignoring the option, and is what this PR does; the index free-list is the missing half. | `crates/kernel/devpts/src/pair.rs` `NEXT_PTS`; `inodes.rs` `allocate_pair` bounds `n` by both `MAX_PTY_PAIRS` and `opts.index_permitted(n)`. | unowned |
| OPEN | COVERAGE | low | **A pty slave's permissions have no in-guest check.** The boot probe reads `/dev/pts/ptmx` and `/proc/mounts`, both of which exist at probe time, but `/dev/pts/0` does not — no pty had been allocated when the probe ran, so the end-to-end stamping is proven hosted (`inodes::slave_stamp_tests`) and not in the guest. A probe that allocates a pty (`script -qc 'stat -c %a:%U:%G $(tty)' /dev/null`) would close it. | Guest output: `PTSRESULT none ptmx=0 opts=rw,relatime,gid=5,mode=620,ptmxmode=000`. | unowned |
