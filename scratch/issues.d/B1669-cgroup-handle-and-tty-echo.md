# B1669 — serial echo duplication: software path exonerated

| Status | Sev | Issue | Evidence | Owner |
|---|---|---|---|---|
| OPEN (narrowed) | med | **Serial tty echo duplicates a character periodically** (`grep -E` → `grep --E`, `env` → `ennv`, `timeout 60` → `timeout 660`). NOT in the line discipline or the staging ring: six new byte-exact tests drive the real RX path (`insert_flip` → `flush_to_ldisc` → N_TTY echo → driver) over 4000-byte streams, across every flush-chunk boundary, with interleaved staging, at ring saturation, and against a concurrent writer, and every one asserts exactly one echoed byte per typed byte. Since the DELIVERED bytes are correct while the ECHOED bytes gain a copy, the extra copy enters strictly downstream of the ldisc's read queue — i.e. in the UART TX path. | `cargo test -p tty --lib echo_stream` (6 tests, B1669). Earlier `flip/tests.rs::a_byte_is_delivered_exactly_once` already excluded the ring. | — |
| OPEN | med | UART TX is unserialized: `drv_serial::emit` polls THRE and writes THR with no lock, and is driven concurrently by klog (any context), the N_TTY echo (flush worker, port lock held, IRQs off) and `TtyStruct::write` (task, `tx` lock held, port lock released). Linux serializes every UART TX with the port lock. Two emitters can both observe THRE=1 and write THR. Prime suspect for the echo-duplication row above. | Read of `drv-uart-16550/src/lib.rs::emit` + `tty/src/core/tty.rs::write` (detached-sink path) vs `core/tty/rx.rs::receive_from_driver` (inline path). Needs a boot lane to confirm; not changed here because the console is the device every lane's boot depends on and this lane cannot boot. | — |
| OPEN | med | The 16550 FIFO is never enabled — nothing programs FCR — so every output byte is a separate THR write and the receiver holds one byte. Linux enables and clears both FIFOs at port startup and sets a receive trigger level. Also makes RX overrun likely on a pasted burst. Second suspect for the duplication row (per-byte THR writes maximize the window in which a blocked host backend retransmits the byte already in the transmit register). | `drv-uart-16550/src/lib.rs` has no FCR write on any path. | — |
| OPEN | low | `set_baud` toggles DLAB and writes the divisor latch at `base+0`/`base+1` with no exclusion against a concurrent `emit`, and readline issues TCSETS on every prompt. A byte written to THR inside that window lands in the divisor latch instead (lost byte + wrong baud). | `drv-uart-16550/src/lib.rs::set_baud`; `SerialTtyDriver::set_termios` calls it on every TCSETS with a non-zero `c_ospeed`. | — |
| OPEN | low | N_TTY echoes `\n` as a bare `\n` rather than through output processing, so ONLCR does not apply to the echoed newline (Linux echoes via the output path, producing `\r\n`). Not the duplication defect; found while proving the echo path. | `ldisc/n_tty/state.rs::echo_byte`. | — |
