# B1982-missing-sched-proc-surface

| Status | Class | Sev | Issue | Evidence | Owner |
|---|---|---|---|---|---|
| OPEN | DEFECT | med | `/proc/<pid>/stat` fields 5 (`pgrp`) and 6 (`session`) render the literal `0`, not the process group and session. The renderer special-cases fields 14, 15, 22, 25, 40, 41 and the memory fields and lets everything else fall through to a zero. `ps -j`, job-control tooling and anything that reads a process's group from procfs sees zero for every process. Found while inventorying the pgid readers, outside this lane's file area. | `crates/kernel/procfs/src/pid_stat.rs` field loop; the values are available on `Task` as `pgid()`/`sid()`. | procfs lane |
| OPEN | MISSING | low | The rseq slice-extension GRANT is a fixed constant, where the reference exposes the extension length as a tunable and drives the revoke from it. Everything else in the feature is implemented and tested; this is the one part that does not track the reference's knob, and the kernel's own claimed release is deliberately capped below the version that introduced it for exactly this reason. | `sched::rseq` `SLICE_EXTENSION_NS`; `syscall::uts` version-claim test explains the cap. | sched lane |
| OPEN | MISSING | med | Per-file tty hangup revocation is still absent (restated with a design after re-verification). The reference revokes each open FILE permanently at hangup by swapping its operation vector, keeping a per-tty list of the open files that reference it; the transient `TTY_HUPPED` bit it clears on every later open is a DIFFERENT mechanism and is the one this tree copied. Here `NTty::hung_up` is one flag per tty and `TtyStruct::open` clears it unconditionally, so a stale descriptor from a dead session becomes usable again the moment the next `login` opens the line. **Negative result that unblocks the fix: NO `vfs` change is needed.** `vfs::File` already carries an unused-by-tty `private_data: AtomicU64`, so a per-open hangup EPOCH can be stamped at open and compared on every operation without mutating `f_op` and without a per-tty file registry. The work is the epoch counter in `crates/kernel/tty` plus the comparison in each tty file-operations implementation — `console`, `devpts` and the virtual-terminal path — which is why it is more than a one-crate change. | `tty/src/ldisc/n_tty/state.rs` (`hung_up`, `clear_hangup`); `tty/src/core/lifecycle.rs::open`; `vfs/src/file.rs` `private_data`, no tty reader in the tree. | tty + console + devpts lane |
| OPEN | MISSING | med | No audit subsystem exists, so the tty-audit surface has nothing to hook to and neither do the Landlock logging flags, the fanotify `FAN_AUDIT` justification or any `AUDIT_*` record. The netlink audit protocol is a 70-line acknowledgement sink: zeroed status, zeroed features, an empty rule list and blanket success for every rule and user record. Re-verified this lane and unchanged. | `crates/kernel/netlink/src/audit.rs`. | needs a lane (audit subsystem) |
| OPEN | COVERAGE | med | Nothing exercises a real kernel-thread exit end to end. The decision halves are hosted-tested (the auto-reap disposition, the exit publication point, the registered-ring teardown), but the actual `kthread_exit` -> final `schedule()` -> post-switch tail -> `kthread_stop` join sequence needs a live runqueue and cannot run hosted, so the first real consumer will be the first execution of that path. The obvious first consumer is a per-ring io_uring submission poller. | `sched::live::kthread::exit`; `live/schedule/switch.rs` reap drain. | io_uring lane (first consumer) |
