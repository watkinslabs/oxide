# B1720 — fsmount(2) returns a real mount

| Status | Class | Sev | Issue | Evidence | Owner |
|---|---|---|---|---|---|
| FIXED (this PR) | DEFECT | high | **`fsmount(2)` returned an anon-inode fd over a deferred object, not a mount.** The fd carried `(sb, root)` and nothing else: `mnt_id == 0`, `FileType::Regular` (so `ENOTDIR` as a dirfd), no mount object at all between `fsmount` and `move_mount`, and nothing to tear down if the fd was simply closed. The reference creates a real `vfsmount`, parks it in an ANONYMOUS mount namespace, and hands back an `O_PATH` fd with `FMODE_NEED_UNMOUNT`. Implemented: `vfs::mount::create_anon_mount` builds a real mount (own id, own root) in a namespace flagged `is_anon`, `fsmount` installs a path fd over it, and `File`'s teardown dissolves it if it was never moved — Linux's `__fput` → `dissolve_on_fput`, at the same place. `move_mount(2)` now grafts THAT mount (`graft_anon_mount_at`), so the id is stable across the move instead of being minted at graft time. | `crates/kernel/vfs/src/mount/anon.rs`, `mntns.rs` (`is_anon`, `allocate_anon`), `file/lifetime.rs` (dissolve hook), `432_fsmount.rs`, `429_move_mount.rs`. 9 hosted tests in `vfs/tests/mount_anon_ns.rs`; positive control: making the namespace non-anonymous turns 3 of them RED. `make smoke` PASS both arches (arm 60s, x86 101s, attempt 1). | B1720 |
| FIXED (this PR) | DEFECT | med | **An anonymous mount was reaped the instant it was created.** `Mount` keys its namespace by id only, with no reference — fine for a mount in a task's namespace, fatal for one whose namespace nothing else holds: `MntNamespace::drop` runs `reap_ns`, which unpublished the mount that had just been published. Linux's `mount` points at its `mnt_ns` with a reference; ours now holds one for the anonymous case (`Mount::anon_ns`), released on graft or dissolve. | Found by the first run of `an_fsmounted_filesystem_is_a_real_mount_before_it_is_moved_anywhere`: `mount_by_id` returned `None` immediately after a successful publish. | B1720 |
| OPEN | INFRA | med | **A `make feature-gate` can report GREEN for the wrong tree.** `cd <worktree> && (gate) & (smoke) & wait` parses as `{ cd && gate } &` then `{ smoke } &` — `&` binds looser than `&&` — so the second job runs in the shell's original directory, normally the MAIN tree. Observed here: the gate type-checked `main` and passed while this branch's kernel build was broken by a missing re-export (`E0425`), which only `make x86` caught. Not a defect in the gate itself (a correctly-targeted run catches it: exit=2 with the error) but a foot-gun that the newly-mandated parallel-checks rule makes MORE likely. `CLAUDE.md` now carries the shape and says to confirm the gate log names your worktree. A `make` guard that refuses to run when `$(CURDIR)` is not the git worktree root of the checked source would remove it entirely. | This lane, twice: gate-exit=0 with `Checking vfs (/home/nd/oxide/kernel/...)` in the log while the worktree was `/home/nd/oxide/kernel-B1720`; after the fix, gate-exit=0 with the worktree's own paths. | unowned |
| OPEN | COVERAGE | med | **A hosted `cargo check -p syscalls` cannot see a break in a slot file.** `432_fsmount.rs`, `429_move_mount.rs` and every other `NNN_*.rs` are `#![cfg(target_os = "oxide-kernel")]`, so a missing re-export used only by a slot file type-checks clean hosted and fails only in the kernel build. This lane hit it exactly once and lost a boot cycle to it. The existing `make feature-gate` is the check that covers this class; nothing makes it obvious that a hosted check does NOT. | `cargo check -p syscalls` clean; `make x86` → `error[E0425]: cannot find function install_mount_path_fd`. | unowned |
