# B1728 — the boot probe path, under the ceiling on both arches

| Status | Class | Sev | Issue | Evidence | Owner |
|---|---|---|---|---|---|
| FIXED (this PR) | DEFECT | high | **`register_netdev` ran the receive softirq inline, putting the entire receive-and-forward chain on the probe's own stack.** The call closed a real lost-wakeup window — a completion landing between the RX ring being filled at probe and the `NetRx` handler being installed raised a softirq with no handler and was dropped, so the first frame (a DHCP OFFER) could sit undrained. But draining it inline meant device registration carried `rx_drain_softirq` → ethernet → IPv6 → TCP listener → transmit → and, because that chain reaches a scheduling point, the whole `schedule()` subtree: **14320 B of a 16384 B stack on aarch64**, 13104 B on x86_64. The reference never calls the poll loop from device registration; it marks the receive half pending and lets the softirq run from the interrupt-exit path. Raising is sufficient here because the handler is installed one line above, so the pending bit is now guaranteed to be serviced — the window the inline drain existed to close stays closed, and the work runs on the interrupt stack where it belongs. | `stack-depth-gate` before/after on clean release builds of both arches. aarch64 `VirtioNetOps::probe` **14320 → PASS** (under the 13000 B ceiling), x86_64 **13104 → PASS**. Both arches now report only the 4 allowlisted boot-stack entries. DHCP verified end to end by `tools/boot-smoke-dhcp.sh`, the smoke that exists for exactly this lost-wakeup risk. | B1728 |
| FIXED (this PR) | DEFECT | med | **`VirtioPciProbeTrace` was built on every probe and never read unless `debug-boot` was on.** ~408 B — including its own copy of the `MAX_RESOURCE_QUEUES` resource array — written into the probe frame and discarded; the type's own doc comment admitted it ("in a default build the record is still built and passed, but no field is ever read") and carried an `allow(dead_code)` to silence the consequence rather than remove the cost. The record, its field in `VirtioProbe`, its construction, its re-export, its call site and the `virtio_trace` module are now all behind the feature whose output is the only reader, so a default build does not construct it at all. | `make feature-gate` PASSes, so the `debug-all` build still compiles every gated line.
