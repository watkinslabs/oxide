| FIXED (this PR) | DEFECT | **critical** | **The kernel installed the emulator's guest address on every virtio-net link at boot, so the network manager never owned the device and never ran DHCP.** `pci-boot` set `10.0.2.15/24` plus a default route on each registered interface, calling it "the boot-time v1 network identity". A kernel does not know its own IPv4 identity — a DHCP client learns it — and a manager that finds a link already carrying an address and a default route it did not configure marks the device externally-connected and declines to own it. It then never activates the link, never performs DHCP, and never publishes the DNS servers the lease carries, which is why `/etc/resolv.conf` had no `nameserver` line and names failed while a query aimed at a server's address still worked. | Guest before: `eth0:connected (externally)`, address present but no `nameserver`. After: `eth0:connected`, `inet 10.0.2.15/24 … dynamic … valid_lft 86345sec` — the `dynamic` flag and the lease lifetime are the proof it came from the DHCP server rather than the seed. | B1737 |
| FIXED (this PR) | DEFECT | **critical** | **Carrier lived in the same flags word userspace writes, so bringing a link up cleared it.** The reference keeps carrier out of `dev->flags` entirely — it is `__LINK_STATE_NOCARRIER` in `dev->state`, owned by the driver through `netif_carrier_on`/`off` — and derives `IFF_RUNNING` / `IFF_LOWER_UP` at read time in `dev_get_flags`, while `__dev_change_flags` never takes the volatile bits from a caller. Here carrier was a stored `IFF_RUNNING` bit in the writable word, so an ordinary "bring this link up" cleared it and the link reported no carrier the instant anyone administered it. The manager, having just brought the device up itself, was told there was no carrier and refused: `Connection 'eth0' is not available on device eth0 because device has no carrier`. Now `IfaceEntry::carrier` is a separate driver-owned bit, `iff::dev_get_flags` derives the two reported bits from it, and `IFF_VOLATILE` is masked out of every userspace write. | Guest: `<NO-CARRIER,BROADCAST,MULTICAST,UP>` → `<BROADCAST,MULTICAST,UP,LOWER_UP>`, and `WIRED-PROPERTIES.CARRIER: off` → the device reaching `connected`. Hosted: five tests covering derivation while down/up/with/without carrier, that a caller cannot forge the bits, and that the volatile mask keeps every administrative bit writable. | B1737 |
| FIXED (this PR) | DEFECT | high | **Two ways to read interface flags, and the link dump used the raw one.** `snapshot_in_ns` reported flags while `iface_flags` returned the stored word, and the `RTM_GETLINK` builder discarded the snapshot's value and re-read the raw one — so the derived carrier bits never reached the wire and a device with carrier still reported `NO-CARRIER`. `iface_flags` is now the single accessor and derives, as the reference funnels every reader through `dev_get_flags`. | `rtnetlink/iface.rs` took `stack.ifaces.iface_flags(id)` and dropped `snap.flags`. | B1737 |
