| FIXED (this PR) | DEFECT | high | **Only `127.0.0.1` was bindable out of the whole loopback prefix, so the stub resolver could not start.** `bind_screen::classify_v4` admitted an address covered by a LOCAL-table route only when the route's `src_hint` equalled the address itself. The loopback route is registered once with `src_hint: Some(127.0.0.1)` for all of `127.0.0.0/8`, so every other loopback address classified `Other` and `bind()` answered EADDRNOTAVAIL. The reference asks the local table for the address TYPE (`RTN_LOCAL` and friends) and never compares the route's preferred-source annotation, which exists to choose a source address on transmit, not to constrain what may be bound. `systemd-resolved` binds `127.0.0.53:53` before it does anything else, so it failed to start at all — which is why no DNS-related line ever appeared in any boot log. | `systemd-resolved.service` gone from `systemctl --failed` on a live-gnome boot after the change.
