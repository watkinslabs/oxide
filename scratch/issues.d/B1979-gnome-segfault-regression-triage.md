| OPEN | DEFECT | High | A process that loads the GIO module `libdconfsettings.so` intermittently dies with `SIGSEGV` on the FIRST read of the dconf database it has just mapped. The faulting instruction is `mov (%rax),%edx` at module offset `0x5245`, where `%rax` is the pointer `g_mapped_file_new()` → `g_mapped_file_get_bytes()` → `g_bytes_get_data()` just handed back and the size check `cmpq $0x17,0x10(%rbx)` has already passed — so userspace holds a mapping the kernel then refuses to fault in. When the victim is `gnome-shell` the whole desktop dies to a bare console; when it is a session service (`evolution-source-registry`) the desktop survives. **Not introduced by the 2026-08-08 wave** — it reproduces on `5506b785e`, the last-known-good commit, at the SAME module offset. | Paired live-gnome boots, same host, same qemu invocation, run concurrently: `910470808` 0 faults / 5 boots, `5506b785e` 1 fault / 5 boots (plus one earlier `910470808` boot under a wider device set, which faulted — so 1/6 vs 1/5, indistinguishable at this sample size). Both fault lines carry `ino 0x6e54000000003e14` (ext4 inode 15892 = `/usr/lib64/gio/modules/libdconfsettings.so`) and `off 0x5245`; only the victim process and the ASLR bases differ. Screendump of the `5506b785e` boot is a black console holding the `gnome-shell` segfault line; every non-faulting boot on BOTH commits reaches the GNOME overview. | FIXED (this branch) | DEFECT | High | A file-mapping fault derived its valid extent from the size read BEFORE the fill and judged the fill against that stale value. An object that SHRANK while the fault was in flight — a writer rewriting a file a reader has already mapped, which is what dconf-service does to the databases every GIO client maps — then made the backing's correct "no more bytes" at the new end look like an unrecoverable short read. The fault failed with `Error::Io`, which reaches userspace as a fatal signal: the reader is killed for the writer's truncate. The reference re-reads i_size AFTER the read completes and decides against that; a page still partly inside the file gets an ordinary zero tail, and only a page wholly past the new end faults. Fixed by re-deriving the extent after a no-progress short and only then declaring the fault fatal. | `vmm::tests_shortfill::a_file_that_shrinks_under_the_fault_is_an_eof_tail_not_a_fatal_short`. Positive control: delete the post-read re-check in `fill.rs` and it goes red with exactly `Io`; the other three short-fill tests stay green, so the guard against installing a partially-zero page (B240) is intact. | Chris Watkins |
