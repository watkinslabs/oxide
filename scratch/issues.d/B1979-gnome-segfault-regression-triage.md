| OPEN | DEFECT | High | A process that loads the GIO module `libdconfsettings.so` intermittently dies with `SIGSEGV` on the FIRST read of the dconf database it has just mapped. | FIXED (this branch) | DEFECT | High | The file-mapping fill gave up on the FIRST read that made no progress and turned it into a fatal fault, which reaches userspace as a killing signal. The reference has no short-read concept at that point: a page is uptodate or it is not, it re-reads a not-uptodate page ONCE synchronously, and only a read that actually ERRORS becomes a fault. Two conditions were therefore lethal here and are not in the reference — a transient no-progress read (page-cache build race, extent boundary) that the next read satisfies, and a file that SHRANK while the fault was in flight, whose extent was still being judged against the size the fault started with, so the backing's correct "no more bytes" at the new end read as unrecoverable. A writer rewriting a file a reader has already mapped is the ordinary case, and it killed the reader. Fixed by re-reading once, re-deriving the extent per attempt, and failing only on a genuine read error or on a page truncated wholly past the new end (the reference's post-read size re-check, whose answer there is a fault, not a zero page). | `vmm::tests_shortfill::a_read_that_stalls_once_is_re_read_not_made_fatal` and `::a_file_that_shrinks_under_the_fault_is_an_eof_tail_not_a_fatal_short`. Positive control: set `FILL_ATTEMPTS` to 1 and BOTH go red with exactly `Io`, the error that becomes the signal; restored, 395 vmm tests green. The three pre-existing short-fill tests stay green, so the B240 guard against installing a partially-zero page is intact. | Chris Watkins |
