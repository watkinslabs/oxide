# B1979 — live-gnome desktop segfault triage

| Status | Class | Sev | Issue | Evidence | Owner |
|---|---|---|---|---|---|
| OPEN | DEFECT | High | A process that loads the GIO module `libdconfsettings.so` intermittently dies with `SIGSEGV` on the FIRST read of the dconf database it has just mapped. The faulting instruction is `mov (%rax),%edx` at module offset `0x5245`, where `%rax` is the pointer `g_mapped_file_new()` → `g_mapped_file_get_bytes()` → `g_bytes_get_data()` just handed back and the size check `cmpq $0x17,0x10(%rbx)` has already passed — so userspace holds a mapping the kernel then refuses to fault in. When the victim is `gnome-shell` the whole desktop dies to a bare console; when it is a session service (`evolution-source-registry`) the desktop survives. **Not introduced by the 2026-08-08 wave** — it reproduces on `5506b785e`, the last-known-good commit, at the SAME module offset. | Paired live-gnome boots, same host, same qemu invocation, run concurrently: `910470808` 0 faults / 5 boots, `5506b785e` 1 fault / 5 boots (plus one earlier `910470808` boot under a wider device set, which faulted — so 1/6 vs 1/5, indistinguishable at this sample size). Both fault lines carry `ino 0x6e54000000003e14` (ext4 inode 15892 = `/usr/lib64/gio/modules/libdconfsettings.so`) and `off 0x5245`; only the victim process and the ASLR bases differ. Screendump of the `5506b785e` boot is a black console holding the `gnome-shell` segfault line; every non-faulting boot on BOTH commits reaches the GNOME overview. Logs: `main-1`, `maina-1..5`, `basea-1..5` under the B1979 scratch dir. | unowned |
| OPEN | COVERAGE | med | Nothing in the tree measures whether a live-gnome boot reaches the desktop, so a desktop-visible regression is only ever found by a human looking at a screen. This triage had to build a one-off harness (boot the profile's ISO with a QMP socket, `screendump` at a fixed deadline, count `segfault at` lines in serial) to get a comparable number out of two commits. | `make` has smoke targets for login and for individual subsystems, none for `PROFILE=live-gnome` reaching `graphical.target`; `tools/boot-report.py` reports `graphical.target: no` for a boot whose serial console is taken over by `debug-shell.service`, which is every live-gnome boot driven through `tools/boot-capture.sh`. | unowned |
