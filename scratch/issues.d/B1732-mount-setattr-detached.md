# B1732 — the last four failed units: `mount_setattr` refused a detached mount

| Status | Class | Sev | Issue | Evidence | Owner |
|---|---|---|---|---|---|
| FIXED (this PR) | DEFECT | high | **`mount_setattr` required the mount to be in the CALLER's namespace, which refused every mount made through the new mount API.** `mnt_setattr_attached` gated on `check_mnt`, i.e. `mount.namespace_id() == current_namespace().id()`. A mount produced by `fsmount(2)` lives in the ANONYMOUS namespace `fsmount` puts it in until `move_mount(2)` grafts it, so that test failed for exactly the sequence the API exists to support: `fsopen` → `fsconfig` → `fsmount` → **`mount_setattr`** → `move_mount`. The reference's `do_mount_setattr` checks only that the path names a mount root (`path_mounted`) and has no namespace test at all. Reaching the mount already proves access — it was named either by a path the caller can resolve or by a descriptor it holds. | Guest, before: `mount -t debugfs -o nosuid,nodev,noexec none /tmp/m` fails (32) while the same mount with no options succeeds. `LIBMOUNT_DEBUG=all` named the failing call outright: `fsopen [success] / fsconfig [success] / fsconfig [success] / fsmount [success] / mount_setattr(set=0x0000000e clr=0x00000000) [Invalid argument]`. After: `opt=0`. | B1732 |
| FIXED (this PR) | DEFECT | high | **Four boot units failed on this one cause, and the whole failed-unit list is now empty.** `dev-mqueue.mount`, `sys-kernel-config.mount`, `sys-kernel-debug.mount` and `sys-kernel-tracing.mount` are all mounted by the service manager with `nosuid,nodev,noexec`, and every one of those goes through the new mount API, so all four died at the same `mount_setattr`. Path-based `mount_setattr` calls were failing too — the trace caught three at `at=0x8100` before the shell was even reachable — so this was not confined to the four units. | `systemctl --failed` after the fix prints NOTHING on a live-gnome boot, with `Transport endpoint is not connected` absent so the query is known to have run. Was 6 failed units at the start of this campaign. | B1732 |

The original row claimed otherwise on the strength of an absent trace, which was the same mistake a second time. The trap was already known and written down in `scratch/done/phases.md` ("`debug-mount` traces MUNMAP, not filesystem mounts") where nothing would surface it. `kmain`'s is renamed `debug-wrotelock`, so the name cannot lie and the old spelling now fails loudly. | Positive control: `--features debug-mount` now exits with `error: none of the selected packages contains this feature: debug-mount` instead of building something unrelated. `--features debug-mnt` build contains both trace strings. | C271 |
