| Status | Class | Sev | Issue | Evidence | Owner |

| OPEN | MISSING | med | An iterator walk emits nothing: the program runs once per object and once at the end of the walk, its answer drives the walk, but no helper can put bytes into the sequence, so every read of a `BPF_ITER_CREATE` descriptor reports end of file. The reference's `bpf_seq_write`/`bpf_seq_printf` copy from the program's stack into the sequence, and the interpreter's helper ABI hands a helper only registers and the shared run state — it has no view of the program's memory, so no helper here could copy a buffer even if it were declared. Needs the helper ABI widened to carry the run's memory, then the two emitting helpers and their argument contracts. | `bpf::iter::seq` runs the walk and returns `Vec::new()`; `bpf_interp::HelperFn` takes `(&mut HelperState, i64 × 5)`. | unclaimed |

Both become observable in the same change that gives the walk an emitting helper (row above). | `bpf::iter::seq::IterMeta`; `bpf_verify::program::tests::iter::following_the_object_pointer_is_refused`. | unclaimed |
