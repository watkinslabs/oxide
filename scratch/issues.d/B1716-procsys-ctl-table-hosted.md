| OPEN | med | **The `/proc/sys` ctl_table still cannot be tested hosted, and this lane measured exactly why.** Carried from the curated row opening "**The `/proc/sys` ctl_table is target-gated, so no hosted test can assert a leaf exists, binds to the right variable, or carries the right mode.**" Widening `procfs::ctl`'s gate to `any(target_os = "oxide-kernel", test)` leaves 11 unresolved references in FOUR distinct cascades, none of which is a procfs decision: (1) `ipc::live::posix_mq::sysctl` — 10 references; `ipc/src/live/mod.rs` carries its own `#![cfg(target_os = "oxide-kernel")]` and the mqueue sysctl accessors resolve the current task's IPC namespace through `live::posix_mq::user::ipc_ns`; (2) `procfs::sysctl` (`bound_sysctl_inode`, `SysctlInode`) — the writable-slot inode machinery, `#![cfg(target_os = "oxide-kernel")]`; (3) `procfs::random_uuid::{make_uuid_inode, make_boot_id_inode}`; (4) `sched::cred` / `sched::live`, which THIS PR's dev-dependency already resolves. What would settle it: hosted halves for `ipc::live::posix_mq::sysctl` (the per-namespace accessor pair, not the queue machinery) and for procfs's own two inode constructors — i.e. the table's *leaves* need their bindings reachable, not the registration walk. Splitting the table into a data-only module is NOT the answer: every hook leaf carries a function pointer to the live variable, so a data-only copy would be a second source of truth. | Measured on this branch: `cargo test -p procfs --lib --no-run` with the gate widened -> `10 error[E0433]: cannot find 'live' in 'ipc'`, `1 error[E0432]: unresolved import 'crate::sysctl'`, plus the two `random_uuid` constructors on the non-test path. Reverted; the gate is unchanged in this PR. | unclaimed |
