## Negative results worth keeping

- **The netlink group gate is NOT a separate `CAP_NET_ADMIN` check on `nl_groups`.**
  The reference has ONE gate covering both a nonzero port and a nonzero group, and
  it is an OR of "this protocol declares its sends unprivileged" with the
  namespace capability. A second, group-only capability check was assumed while
  planning this lane and does not exist.
- **`nonroot_send` is declared by exactly one protocol.** Every other one — the
  routing, generic, audit and uevent protocols included — is gated. This is worth
  knowing before blaming the new gate for a boot regression: a privileged daemon
  is unaffected, an unprivileged multicast sender is not.
