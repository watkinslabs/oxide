| FIXED B1706 | high | `ptrace` read the x86_64 tracee's saved entry frame as **16 quadwords at `kernel_stack - 0x80`** while the frame the entry asm pushes is **22 quadwords at `kernel_stack - 0xb0`**. Consequence was silent wrong data, not a crash: `PTRACE_GETREGS` / `PTRACE_GETREGSET(NT_PRSTATUS)` / `PTRACE_PEEKUSER` reported the frame's `r11` as `orig_rax` and its `rcx` as `rip`, and `PTRACE_SETREGS` / `POKEUSER` wrote a debugged process's registers into the wrong slots. Invisible at a syscall stop (the `syscall` instruction genuinely parks the user RIP in `rcx`), visible at every fault/signal stop — i.e. exactly the attach a debugger performs. Fixed by deriving both the base and the field access from `PtRegs`, the struct the entry path pushes. | `t_ptrace_getregs` (new, `userspace/glibc_conformance/`): `pc_in_crash_fn` and `setregs_redirected_pc` at a SIGSEGV stop. Hosted: `s101_ptrace_regs::tests::x86_tests::*` (14 tests, was 9). Positive control: `u[U_RIP] = f.rcx` turns `x86_frame_maps_onto_the_right_user_regs_fields` and `x86_round_trip_preserves_every_general_register` RED. | B1706 |
| FIXED B1706 | med | Split source of truth about register layout: the live ptrace path carried its own frame offset table AND its own `struct user_regs_struct` index table, both duplicated by the core-dump `NT_PRSTATUS` path. Two paths could (and did) tell different stories about the same task. Frame layout now has one owner per arch (`PtRegs` / `SvcFrame`, reached by field name — no offsets restated anywhere); the ABI index tables have one owner (`hal::uregs::{x86_64::user_regs, aarch64::user_pt_regs}`) that `syscalls/101_ptrace` and `fs/coredump/gregset` both consult. | `crates/arch/hal/src/uregs.rs`; both consumers now `pub use` the same constants. | B1706 |
| FIXED B1706 | med | `PTRACE_GETREGS` reported a stale `rax` and a bogus `orig_rax` at any NON-syscall stop. `orig_rax` came from a frame slot that has no syscall meaning on a trap frame, and `rax` always came from the task's `ptrace_stop_rax` cell, which is only written at syscall stops — so a tracer stopped on SIGSEGV read whatever the last syscall stop left there. Now follows the frame's entry tag: on a `syscall` frame `rax` is the recorded stop value and `orig_rax` the syscall number; on a trap frame `rax` is the architectural register and `orig_rax` is the no-syscall marker, which is what the core-dump block already reported for the same frame. | `x86_trap_frame_reports_no_syscall_and_the_architectural_rax`, `x86_setregs_on_a_trap_frame_installs_the_architectural_rax`. | B1706 |
| OPEN | low | aarch64 has no independent `orig_ax` equivalent and x86_64 here deliberately keeps ONE `rax` slot serving both roles (`PtRegs` header documents the split of Linux's overloaded `orig_ax` into `vector`/`error`). A tracer therefore cannot set `orig_rax` and `rax` to independent values on a trap frame: the write side picks the slot by entry tag. Linux has two distinct slots and would honour both. Not fixed because giving the frame a second slot changes an asm-coupled layout on both arches; recorded so the next lane touching `PtRegs` sees the cost. | `from_user_regs` in `crates/kernel/syscalls/src/101_ptrace/regs.rs`; pinned by `x86_setregs_on_a_trap_frame_installs_the_architectural_rax`. | — |

| OPEN | high | `PTRACE_GETSIGINFO` reports a fault record as a kill record, and fills `si_addr` with the TRACER's pid. Two causes, both in the ptrace stop path: (1) `sig.rs::getsiginfo` writes only the `_kill` arm of the `siginfo_t` union (`signo@0`, `code@8`, `pid@16`, `uid@20`, `value@24`) and never consults `SigInfo.fault` / `.sys` / `.poll`, so `si_addr` — which occupies bytes 16..24 in the `_sigfault` arm — is never written; (2) `stop.rs::notify_with` substitutes the tracer's pid into `info.pid` whenever it is zero, unconditionally, so on a SIGSEGV record that word lands in `si_addr`. A debugger therefore cannot learn the faulting address of the process it is attached to. NOT fixed here: this lane is the register frame, and the fix is a siginfo-encoding change with its own union-arm test matrix. | Measured in-guest: `t_ptrace_getregs` with an added `si_addr == NULL` check at a SIGSEGV signal-delivery stop printed `fault_addr_null=0` where the host oracle printed `1` (run `conformance-x86_64.IKtsha`). The check was dropped from the shipped probe so it stays scoped to registers; re-add the four lines to reproduce. | — |
