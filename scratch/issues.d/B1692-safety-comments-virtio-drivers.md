# B1692 — SAFETY comment audit, virtio + display + storage drivers

Audit of every `code/safety-missing` / `code/safety-short` finding in
`crates/drivers/{virtio,drv-virtio-*,drm,fbdev,fbcon,drv-nvme,drv-ahci}`.
Each block was read and its invariant established before a comment was written;
blocks that turned out unsound are rows below, not comments.

| FIXED B1692 | HIGH | `program_queue` used the DEVICE-supplied `queue_size` unchecked while allocating exactly ONE frame per ring area. A device advertising more descriptors than a frame holds (QEMU accepts `queue-size=1024` on virtio-blk) makes every driver's own descriptor/avail/used store run off the end of that frame — a kernel heap wild write whose value comes from the ring index. Now renegotiated down per Virtio 1.2 §4.1.4.3 and the queue refused if the device does not accept. | `virtio::queue_cfg::tests::oversized_device_queue_size_is_negotiated_down_to_one_frame`; positive control: with the clamp disabled the test FAILS (`ring.size` 1024 vs 256), with it enabled it passes | B1692 |

On an unconfirmed reset this returned a physical address the device still lists as resource backing to the buddy allocator. | `post_init::release::tests::an_unconfirmed_reset_releases_nothing_so_the_device_keeps_its_frames`; positive control: with the reset gate removed from `releasable_dma` that test FAILS, with it present it passes | B1692 |

| FIXED B1692 | HIGH | DRM ioctls dereferenced USER pointers raw (`read_volatile(arg as *const T)`) behind nothing but a range check. A range check proves the address is in the user half, not that it is mapped readable; such a dereference from kernel mode has no exception-table entry, so the fault handler finds no VMA, `handled=false`, and the CPU OOPSes and halts — an unprivileged local DoS via any bogus ioctl pointer. It also imposed the struct's alignment on a pointer userspace chose. Converted `dumb/ioctl.rs`, `node/atomic_ioctl.rs` and `kms_ext.rs` cursor paths to a new `drm::uarg` that goes through `uaccess::copy_{from,to}_user` (exception-table-backed) and `read_unaligned`. | `drm::uarg::tests::a_null_user_pointer_is_reported_not_dereferenced`, `…::every_drm_ioctl_arg_struct_fits_the_transfer_buffer`; `crates/kernel/uaccess/src/copy.rs` vs `hal-x86_64/src/fault.rs:229` (fixup only for exception-table RIPs) | B1692 |
| FIXED B1692 | HIGH | `MODE_ATOMIC` summed the per-object property counts in `atomic_property_count`, range-checked `props_ptr`/`prop_values_ptr` against that total, then RE-READ each per-object count from the same user array in the copy loop. Userspace rewriting `count_props[]` between the two passes walked the flattened index past the checked extent, reading `props_ptr + pos*4` outside it — a user-controlled out-of-range read whose values reach `atomic::commit`. The running total is now re-checked per object. | `node::atomic_ioctl::tests::a_count_grown_since_validation_is_refused` + `an_overflowing_running_total_is_refused`; positive control: deleting the `end > count` guard makes the first FAIL | B1692 |
