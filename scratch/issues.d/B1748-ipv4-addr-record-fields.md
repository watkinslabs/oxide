# B1748 — IPv4 address record fidelity

| Status | Class | Sev | Issue | Evidence | Owner |
|---|---|---|---|---|---|
| FIXED B1748 | DEFECT | high | `RTM_NEWADDR` parsed `IFA_BROADCAST` and threw it away (`broadcast: None` unconditionally), and never parsed `IFA_PROTO` or `IFA_RT_PRIORITY` at all. The dump then **synthesized** a broadcast from the prefix and reported no proto. NetworkManager read back an address that did not match the one it set and re-applied it every 4 s for the entire boot — 63 `RTM_NEWADDR`, zero `RTM_DELADDR`, in one 570 s trace. | `crates/kernel/netlink/src/rtnetlink_tests/addr_fields.rs`; positive control: restoring the synthesis turns two suites RED | — |
| FIXED B1748 | DEFECT | med | Address lifetimes were never aged: the stored `ifa_cacheinfo` was reported verbatim forever, so a DHCP client saw a lease whose remaining time never decreased, and a permanent address did not report infinity. The setter's `cstamp`/`tstamp` were also echoed back rather than replaced with the install time. | `crates/kernel/net/src/iface_addr/lifetime.rs` — 7 hosted tests over `age`/`stamp` | — |
| FIXED B1748 | DEFECT | med | Two address row types existed side by side — `net::iface_addr::Ipv4IfaceAddr` and `netlink::rtnetlink_addr::IfaceAddr` — and the conversions between them dropped `broadcast` in both directions. Both now carry every field, so a round trip through either is lossless. | `addr_to_net` / `addr_from_net` | — |
| OPEN | DEFECT | low | The two row types are still a split source of truth: one carries typed `Ipv4Addr`/`NetIfaceId`, the other `[u8; 4]`/`u32`, and every field added to one must be added to the other or it is silently dropped — which is exactly how `broadcast` was lost. Eleven non-test references; the netlink-side type should be deleted and the `net` one used throughout. | `crates/kernel/netlink/src/rtnetlink_addr.rs` `IfaceAddr` | — |
| OPEN | MISSING | low | `IFA_ANYCAST`, `IFA_MULTICAST` and `IFA_TARGET_NETNSID` are still neither parsed nor reported. The reference carries all three. | `parse_newaddr_attrs` rejects unknown-but-known types only for the ones it names | — |
