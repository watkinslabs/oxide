# B1744 — SOL_NETLINK option surface

| Status | Class | Sev | Issue | Evidence | Owner |
|---|---|---|---|---|---|
| FIXED B1744 | DEFECT | med | `setsockopt(SOL_NETLINK, …)` returned success for every optname it did not implement — `NETLINK_PKTINFO`, `BROADCAST_ERROR`, `RX_RING`, `TX_RING`, `LISTEN_ALL_NSID`, `CAP_ACK`, `EXT_ACK`, `GET_STRICT_CHK`. Linux returns `ENOPROTOOPT` for anything outside its switch and stores the rest in the socket's `NETLINK_F_*` word. A client that sets an option and is told it succeeded then observes the unmodified behaviour. | `netlink_fd.rs` `setsockopt` fell through a `matches!` of three optnames and returned `0`; `sockflags.rs` tests now pin every optname to its action, incl. `RX_RING`/`TX_RING` → `Unknown` | — |
| FIXED B1744 | DEFECT | low | `getsockopt(SOL_NETLINK, …)` answered only `NETLINK_LIST_MEMBERSHIPS`; every boolean option returned `ENOPROTOOPT` where Linux reports the flag bit. | `sockflags::get_answer` + `netlink_fd.rs` `getsockopt` | — |
| FIXED B1744 | DEFECT | low | `NETLINK_ADD_MEMBERSHIP`/`DROP_MEMBERSHIP` took no capability check. Linux requires `CAP_NET_ADMIN` unless the protocol declares `NL_CFG_F_NONROOT_RECV` (rtnetlink, genetlink, sock_diag, audit, uevent do; netfilter does not). `NETLINK_LISTEN_ALL_NSID` requires `CAP_NET_BROADCAST`. | `sockflags::nonroot_recv` + `has_net_admin`/`has_net_broadcast` in the shim | — |
| FIXED B1744 | DEFECT | low | `optlen < sizeof(int)` returned `EINVAL` and `optval == 0` returned `EINVAL`. Linux skips the copy for a short option (value stays 0) and reports `EFAULT` for a bad pointer. | `netlink_fd.rs` `setsockopt` | — |
| FIXED B1745 | MISSING | med | `NETLINK_F_STRICT_CHK` is now stored and readable but not consumed.
