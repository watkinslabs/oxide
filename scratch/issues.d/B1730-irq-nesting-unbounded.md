# B1730 — the `#DF`: unbounded interrupt nesting, not frame bloat

| Status | Class | Sev | Issue | Evidence | Owner |
|---|---|---|---|---|---|
| FIXED (this PR) | DEFECT | high | **x86_64 sent EOI BEFORE the interrupt handler ran, so a source that was still asserted could re-interrupt while its own handler was executing.** The reference sends it after — `handle_irq_event(desc)` then `cond_unmask_eoi_irq(desc, chip)` — precisely so the in-service bit stays set for the handler's whole duration and the same source cannot re-enter. Ours EOI'd at the top of `oxide_irq_dispatch`, clearing the in-service bit immediately, so a serial port whose receive FIFO refills as fast as it is drained re-interrupted the moment interrupts came back on. aarch64 already had this right (`gic/dispatch.rs` EOIs after `invoke_arm_irq_handler`), so this was a lockstep gap, not an unknown. | `lapic/dispatch.rs` EOI moved from before the `match vec_tag` to after it. | B1730 |
| FIXED (this PR) | DEFECT | high | **The bottom-half count was taken INSIDE the drain, after interrupts were re-enabled, leaving a window in which nesting was unbounded.** `irq_exit()` dropped the hardirq count, the dispatcher then executed `sti`, and only afterwards did `do_softirq` add `SOFTIRQ_OFFSET`. An interrupt arriving between the `sti` and that add saw `in_interrupt() == 0`, concluded it was free to drain, and opened its OWN interrupt-enabled window — and so could the next one, and the next, all on the single 16 KiB per-CPU interrupt stack with no depth bound anywhere in `dispatch.rs`, `irq.rs` or `preempt.rs`. The reference closes exactly this by disabling bottom halves while interrupts are still off (`irq_exit_rcu` → `__local_bh_disable_ip(SOFTIRQ_OFFSET)`) and enabling them inside the drain. `bh::softirq_tail_{begin,run,end}` split the accounting so the dispatcher takes the count before `sti` and releases it after `cli`; the `sti`/`cli` stay in arch code. Nesting is now bounded at two levels: a nested dispatch's `softirq_tail_begin()` returns false, so it never opens a window and runs entirely with interrupts off. | The probe that reproduced the fault twice (live-gnome, typing at the serial console) now shows **0 `#DF` and 0 guard-page hits**. Before: `BUG: IRQ stack guard page was hit (stack is fffffb0000006000..fffffb000000a000, rsp=fffffb0000006000, headroom=0)`. | B1730 |
| FIXED (this PR) | COVERAGE | high | **A guard-page hit reported raw registers and could not say which stack overflowed.** Task stacks and the per-CPU interrupt stack are slots of ONE allocator window, so `rsp` sitting on a boundary named neither — and the two have different budgets and opposite fixes. The question was answered by hand, from a register dump, across several sessions. The reference classifies the faulting address in its double-fault handler and prints the stack's name and bounds; that is now what happens here, plus the most-repeated return address on the dead stack, which is what distinguishes unbounded nesting from a genuinely deep chain. The distinction mattered: a static depth walk put the whole interrupt path at ~8.7 KB of 16 KB and passed, while the same kernel ran that stack to zero — a gap that is only explicable by repetition, because the walk measures one pass. | First run with the classifier: `BUG: IRQ stack guard page was hit … headroom=0` — one line, where three sessions of register-reading had gone before. `crates/kernel/sched/src/kstack/classify.rs` + tests: 14 hosted tests, including the observed fault address reproduced as arithmetic. | B1730 |
| OPEN | MISSING | high | **No spurious- or storm-protection anywhere, unlike the reference's two layers.** The reference bounds a single interrupt-line pass (`serial8250_interrupt`'s `PASS_LIMIT` of 512) and, in the generic IRQ core, counts unhandled interrupts per line and DISABLES the line once they cross a threshold without an intervening handled one (`kernel/irq/spurious.c` `note_interrupt`). Here there is no per-line unhandled counter, no pass limit and no auto-disable, so a genuinely stuck source has nothing to stop it — this lane removed the mechanism by which a burst became unbounded, but not the failsafe for a device that never deasserts. | Whole-tree search for an unhandled-interrupt counter or pass limit returns nothing. | unowned |
| OPEN | MISSING | med | **No interrupt-nesting depth bound and no runtime stack high-water mark.** Nesting is now structurally bounded at two levels, but nothing measures or enforces it, so a future change that reopens a window fails the same silent way.
