# B1740 — a cgroup write naming a leaving task was an error, not a skip

| Status | Class | Sev | Issue | Evidence | Owner |
|---|---|---|---|---|---|
| FIXED (this PR) | DEFECT | **critical** | **`make qemu-x86-debug` froze at boot because `migrate_hook` reported ESRCH for a task on its way out.** The reference does not: `cgroup_migrate_add_task` returns without acting when `PF_EXITING` is set — *"@task either already exited or can't exit until the end"* — and the part that CAN fail, `cgroup_procs_write_start`, rejects only a pid that resolves to nothing (ESRCH) or a kthread pinned by `PF_NO_SETAFFINITY` (EINVAL). It never turns "this task is leaving" into an error, because the write asks for a state the task is about to reach anyway: nothing to move, nothing to report. The service manager took the ESRCH at its word — `Failed to create /init.scope control group: No such process`, then `Freezing execution.` — and every debug boot hung at t≈28.5 s. The destination is now returned as the source, so the caller sees a move from where it already is. | A full `--features debug-all` boot now reaches userspace and answers on serial: `boot-smoke: PASS … in 253s`, with **zero** `control group` or `Freezing execution` lines, where every previous debug boot froze. Hosted: `a_migration_naming_an_exiting_task_is_skipped_not_refused` and `a_migration_naming_an_unknown_pid_is_still_esrch`, so the one failure the reference does report is still reported. Positive control: restoring the ESRCH fails the first with `an exiting task must be skipped, not refused: Esrch`. | B1740 |
