| FIXED (this PR) | MISSING | high | **cgroup2 discarded every mount option.** It registered with `FsType::new` (no parameter table) and its constructor took `_` for the data string, so `-o nsdelegate,memory_recursiveprot` — what systemd passes on a modern distro — never reached the hierarchy. All six reference flags are now declared (`cgroup2_fs_parameters`) and stored in a hierarchy-root flag word using Linux's own `CGRP_ROOT_*` bit values, merged rather than replaced on a second mount so one mount cannot silently clear another's delegation boundary, and rendered by `show_options` in declaration order. | `crates/kernel/cgroup/src/root_flags.rs` (8 tests), `state.rs` (`root_flags`/`add_root_flags`), `fs.rs` (`show_options`), `registry.rs`. | B1722 |
| FIXED (this PR) | DEFECT | high | **`nsdelegate` had no enforcement point at all.** A cgroup namespace existed only as a display remap (`nscg::cgroup_ns`, consumed solely by `/proc/<pid>/cgroup`); `cgroup.procs` writes consulted it nowhere, so a task in a delegated namespace could migrate a process into any cgroup in the hierarchy. Now the write path asks the reference's question (`cgroup_procs_write_permission`): under `nsdelegate`, both the source and destination must be visible from the caller's namespace root, and a write across the boundary is **ENOENT** — not EPERM, because the cgroup is not supposed to exist as far as the caller is concerned. The boundary test compares path COMPONENTS, so `/podxyz` is not inside `/pod`. | `tree/hierarchy.rs::is_under_path`, `lib.rs::write_file` gate, `state.rs::caller_ns_root` hook installed by `registry.rs`. Tests in `tests/root_options.rs`. Positive control: replacing the component compare with a raw string prefix turns 2 tests RED, and the failing case is the escape (`/podxyz` reads as inside `/pod`). | B1722 |
