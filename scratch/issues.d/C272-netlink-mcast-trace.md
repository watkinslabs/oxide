| FIXED C272 | INFRA | med | A notification nobody received was indistinguishable from one never sent: nothing reported which sockets existed, which were subscribed, or how many the message reached. Three DNS investigations theorized delivery bugs that this would have refuted in one boot. | `debug-netlink` now emits `[NL-MCAST ns= grp= live= subscribed= reached= type= bytes=]` per broadcast and `[NL-SUB tid/comm proto= add=/bindmask=]` per subscription | — |
| OPEN | DEFECT | high | NetworkManager re-applies eth0's IPv4 address every 4 s for the entire boot — 63 `RTM_NEWADDR` in one 570 s trace, no `RTM_DELADDR`. Real Linux announces an address once. `handle_newaddr_in` parses and then **discards** `IFA_BROADCAST`, and does not parse `IFA_PROTO` or `IFA_RT_PRIORITY` at all; the dump then synthesizes a broadcast from the prefix and reports no proto. NM reads back an address that does not match what it set and re-applies forever. | `[NL-MCAST ns=0 grp=5 … type=20]` at 13.3 / 17.3 / 21.3 / … / 569.7 s; `crates/kernel/netlink/src/rtnetlink/addr_ops.rs` `parse_newaddr_attrs`, row built with `broadcast: None` | — |
| OPEN | DEFECT | med | Address lifetimes are never aged. The reference subtracts elapsed time from `preferred`/`valid` on every readback and reports `INFINITY_LIFE_TIME` for a permanent address; ours reports the stored `ifa_cacheinfo` verbatim forever, so a DHCP client sees a lease whose remaining time never decreases. | `crates/kernel/netlink/src/rtnetlink/dumps.rs` `build_newaddr_reply` writes `cacheinfo` unmodified | — |
