# F783-memfd-create-audit

| Status | Sev | Issue | Evidence | Owner |
|---|---|---|---|---|
| OPEN | high | `main` does not build `net` as a plain dependency: `sock` and `sock_opts` are gated `any(target_os = "oxide-kernel", test, feature = "hosted")`, but the ungated `send_control`, `ipv4_options`, `raw4` and `stack` modules name `crate::sock_opts` unconditionally. `cargo check -p net` and `cargo test -p fs` fail with 9 errors on a pristine `origin/main` (09d4695a3); a multi-package run stays green because feature unification enables `net/hosted`, which is why CI and every earlier lane missed it. Ungating `sock_opts` alone is not enough — it cascades into `sock`. The correct fix is to move the shared IP-option UAPI types out of the gated `sock_opts` into the ungated `ipv4_options` and re-export them, which is a `net` module-ownership change and belongs to a net lane. | F783; `cargo check -p net` on 09d4695a3. Introduced by PR #4342 (`B1662-ip-sockopt-consumers-b`). | — |
| OPEN | low | `memfd_create(MFD_HUGETLB)` returns ENOSYS because there is no hugetlbfs in this kernel at all — consistent with `mmap(MAP_HUGETLB)` returning EINVAL and with `cachestat`'s unreachable hugepage EOPNOTSUPP leg. This is the answer an unconfigured hugepage build gives, not a stub, but it IS absent Linux surface: a real distro kernel has `CONFIG_HUGETLBFS=y`. Closing it means a hugetlbfs lane, not a memfd change. | F783; `319_memfd_create.rs` hugetlb leg. | — |
| OPEN | low | `memfd_wait_for_pins` has no counterpart: `F_ADD_SEALS(F_SEAL_WRITE)` checks `mapping_deny_writable` (writable shared mappings, EBUSY) but not long-term page pins, because nothing in this kernel long-term-pins a page. Truthful today. It becomes a real hole — data written behind a write seal — the moment a GUP-style pin (io_uring registered buffers over shmem, zero-copy RX) can outlive the syscall that took it. | F783; no `pin_user_pages` equivalent exists (grep clean). | — |
| OPEN | low | `security_inode_init_security_anon` has no counterpart anywhere in the kernel, so memfd (and every other anon inode) is created without an LSM labelling hook. Not memfd-specific and not observable without an LSM that labels inodes; recorded so the anon-inode creation sites are known when one lands. | F783; grep for `inode_init_security` returns nothing. | — |
| OPEN | low | The `memfd_create` matrix row's notes column had been column-broken since B1542 by unescaped `|` characters, splitting the notes across fields 13-15. Status (`$9`) and branch (`$10`) still parsed, so tooling did not notice, but the notes read as truncated. Rejoined in F783. Other rows may carry the same defect — a matrix lint for `NF != 14` would catch it. | F783; the row had 16 pipe-separated fields. | — |
| OPEN | high | The compliance matrix on `main` carries **66 duplicate-numbered rows**: the `F784-matrix-untracked-syscalls` completeness pass appended rows for syscalls that were already tracked instead of reconciling with the existing ones, so 66 slots now have two rows with different `Status` and different `Notes` — e.g. `319:memfd_create` had one `PARTIAL` row and one `NEEDS-AUDIT` row. Any tooling that reads status as awk `$9` gets whichever row it hits first, and the row authority rule ("add/remove/renumber rows only by re-reading `syscall_64.tbl`") is what should have caught it. Reproduction: `awk -F'\|' '{n=$2; gsub(/ /,"",n); if (n ~ /^[0-9]+$/) print n}' scratch/syscall-compliance-matrix.md \| sort -n \| uniq -d \| wc -l` → 66. F783 removed only the duplicate `319` row, the one this PR audits; the other 65 belong to the F784 lane. A matrix lint asserting one row per number (and `NF == 14`) would prevent recurrence. | F783; `awk` count above against `origin/main` 5b7cd66a9. | F784 lane |
