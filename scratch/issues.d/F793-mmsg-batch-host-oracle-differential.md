Findings from building the row-299/307 host-oracle corpus. Rows promoted: none.

| FIXED F793 | HIGH | `conformance::outcome::same_errno_class` compared the errno only when the outcome was a SUCCESS (`!self.is_success() \| self.errno == other.errno`), i.e. never — on a failure the guard short-circuits true. Every `Case` in every conformance corpus therefore matched on success/failure CLASS alone, and an oxide errno of any value passed against any host errno. The harness that exists to prove error ordering could not observe a wrong errno. | Flipping the guard to `self.is_success() \|\| ...` immediately turned up two hidden cases (both below). Mutating any of the eight recvmmsg batch rules now turns `conformance_mmsg` red; before the fix, four of the eight mutations passed silently. | F793 |
| FIXED F793 | MED | `vfs` corpus case `write.directory.eisdir` asked the two kernels different questions: the host side wrote to a directory opened `O_RDONLY` (the only mode Linux allows) and got EBADF from the writability check, while the oxide side was handed an `O_RDWR` directory `File` — a description no Linux `open` returns — and answered EISDIR. Hidden by the comparator defect above. | Case renamed `write.directory.not_writable` and given `O_RDONLY` on both sides; oxide already checks writability before the directory type, so both now report EBADF. NOT a kernel divergence. | F793 |
| FIXED F793 | MED | `path_ops_ladder_oracle::trailing_slash_splits_mkdir_from_symlink_on_the_host` computed the oxide verdict AFTER the `mkdir` that materialises the fixture, so the policy was asked about an existing name (EEXIST) while the host had been asked about a free one (ENOENT). Hidden by the comparator defect. | Verdict now taken while the name is free; `check_create_leaf` was correct all along. NOT a kernel divergence. | F793 |
| FIXED F793 | MED | The recvmmsg batch ORDER was a split source of truth: `299_recvmmsg.rs` (target-gated) composed the rules, and `mmsg_batch::tests` re-implemented that composition in a test-local `drive` helper. The unit tests proved a copy of the kernel matched Linux, not the kernel. Two source-grep assertions in `net_common` stood in for the ordering evidence. | Composition moved to ungated `mmsg_batch::run` behind a `BatchOps` trait; the slot file implements it and holds no loop; unit tests and the new corpus drive the real runner. The `net_common` greps for the old textual order are replaced. | F793 |
