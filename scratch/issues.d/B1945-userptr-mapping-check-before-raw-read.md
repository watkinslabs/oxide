| FIXED | DEFECT | high | `syscall::scan_user_cstr` range-checked each address and left the byte read to a caller-supplied closure, every one of which read raw. A range check is `access_ok`; it is safe in the reference ONLY because the load carries an exception-table fixup. These loads carried none, so an address merely inside the user half that nothing maps faulted the KERNEL instead of answering EFAULT — from `execve`'s pathname, `memfd_create`'s name, `delete_module`'s name and the keyring's type/description.
