# B1673 — variable-length handshake options (TFO groundwork, stage 1)

| Status | Sev | Issue | Evidence | Owner |
|---|---|---|---|---|
| FIXED B1673 | med | The handshake option area was fixed at 20 bytes with `data_offset` hard-coded to 10, so every SYN **and** SYN-ACK carried exactly MSS + window-scale + timestamps whether or not those options had been negotiated. A SYN-ACK answering a bare SYN offered window scaling and timestamps the peer never asked for — turning both features on unilaterally. | `tcp_conn/segment.rs` `build_syn_with_opts_at`: `const OPTS_LEN: usize = 20`, `data_offset: 10`. Now assembled by `tcp_conn/syn_opts.rs` from a descriptor; `a_syn_ack_echoes_only_the_options_the_peer_offered`. | B1673 |
| FIXED B1673 | med | `SACK_PERMIT` (kind 4) was never emitted — the constant and `parse_sack_permitted` existed with **zero callers**, so this side never advertised selective acknowledgement and never learned whether the peer did. Machinery without callers, the same class as the `TCP_DEFER_ACCEPT` and keyring rows. | `grep parse_sack_permitted` returned only its own definition. Now offered on every SYN and echoed on a SYN-ACK when the peer offered it; `an_opening_syn_offers_every_option_this_side_supports`. | B1673 |
| FIXED B1673 | high | `build_ack_with_sack` emitted SACK blocks **unconditionally**, to peers that had never permitted them. `sack_ok` existed but was only ever set by `TCP_REPAIR_OPTIONS`, never by the handshake, so the negotiated state it represented was never negotiated. A peer that declined the option is entitled to treat the blocks as a malformed option area. | `tcp_conn/sack.rs`. `sack_ok` is now set from the peer's SYN / SYN-ACK and gates emission; `sack_blocks_are_withheld_from_a_peer_that_did_not_permit_them` fails without the gate. | B1673 |
| FIXED B1673 | med | An active open set `snd_wscale = OWN_WSCALE` before sending its SYN and never took it back when the SYN-ACK omitted the window-scale option. The connection went on shifting every advertised window right by the scale while the peer, having declined scaling, read those windows unshifted — a silently under-advertised receive window for the life of the connection. | `tcp_conn/io.rs` `SynSent` arm. New `wscale_ok` field records the negotiation; `a_peer_that_declines_scaling_takes_this_sides_scale_down_with_it`. | B1673 |
| OPEN | med | Data segments still carry timestamps keyed on `ts_enabled` alone (`build_segment_at`), which is correct, but the SACK-block writer in `sack.rs` and the timestamp writer in `segment.rs` each assemble their own option area by hand rather than through `syn_opts`. Two more hand-rolled option writers remain; a non-SYN option assembler should absorb them. | Not a live defect — both currently emit correct bytes. Flagged so the next lane in this area does not add a fourth. | — |
| OPEN | low | `TCP_MAX_WSCALE` (14, RFC 7323 ceiling) is enforced on the `TCP_REPAIR_OPTIONS` path but a peer's advertised scale is taken verbatim from the wire into `rcv_wscale` with no ceiling check. A peer advertising 255 would have its shift applied to every window this side computes. | `tcp_conn/io.rs` both parse sites; `parse_wscale_option` does not clamp. Out of scope for this lane. | — |
