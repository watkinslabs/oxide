# F780-process-madvise-mrelease

| Status | Sev | Issue | Evidence | Owner |
|---|---|---|---|---|
| OPEN | low | `process_mrelease` cannot report `EINTR` or `EAGAIN`. Upstream returns `EINTR` when the killable mmap read-lock is interrupted and `EAGAIN` when the reaper cannot take that lock; this kernel's reap walk takes an uninterruptible VMA guard and cannot fail, so neither state exists to report. A caller that retries on `EAGAIN` is not misled — it never sees one — but the two errnos become real once the reap is made lock-failure-tolerant. | F780; `crates/kernel/syscalls/src/448_process_mrelease.rs`. | — |
| OPEN | low | `process_mrelease` reads `coredumping` as always false, because nothing in this kernel writes a core dump on the exit path. Upstream refuses to reap a dumping task since it can sleep for a long time before releasing anything. The predicate is implemented and tested (`a_coredumping_task_is_refused_despite_dying`); only the input is hardwired. Wire it to the real state when core dumps land. | F780; `exit_state()` in the slot file. | — |
| OPEN | low | `process_mrelease`'s mm-sharer scan is O(all tasks) per call: it walks the registry snapshot to find CLONE_VM peers outside the thread group, because there is no per-mm task list. Correct, but it makes a syscall meant for OOM-response paths scale with total process count. A back-pointer list on `AddressSpace` would make it O(sharers). | F780; `sys_process_mrelease`. | — |
| OPEN | med | `process_madvise` no longer carries its own permission check beyond `mm_access(PTRACE_MODE_READ_FSCREDS)` + `CAP_SYS_NICE`, and `process_mrelease` now has NO permission check at all — the pidfd is the whole authority, matching upstream, where the previous `sig_perm_check` EPERM had no counterpart. This is deliberate Linux parity and is the reason `task_will_free_mem` has to be exact: the "is the target really dying" ladder is the only thing standing between a pidfd holder and another process's pages. Recorded so a future audit does not read the removed check as an accident. | F780; upstream `SYSCALL_DEFINE2(process_mrelease)` has no permission gate. | — |
