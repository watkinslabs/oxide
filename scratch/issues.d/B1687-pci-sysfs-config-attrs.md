# B1687 — PCI sysfs attribute surface

| Status | Sev | Issue | Evidence | Owner |
|---|---|---|---|---|
| FIXED B1687 | CRITICAL | A PCI function published only `vendor`, `device`, `class`, `resource`, `modalias`, `driver_override` and `uevent`. libdrm's device enumeration counts devices on a pass that only needs the directory, then fetches the full identity on a second pass that needs `revision`, `subsystem_vendor`, `subsystem_device` (falling back to the raw `config` blob). The fetch pass dropped every device, so `drmGetDevices2(0, NULL, 0)` returned 1 and `drmGetDevices2(0, arr, 1)` returned 0 with a NULL slot. A Vulkan ICD that sizes its loop from the first count then dereferenced an unwritten slot, killing GTK4's default renderer — gnome-control-center and nautilus both SIGSEGV'd on start. | `bus::tests::pci_dev_attrs::*` (4); `bus::pci_attrs::*` (26); in-guest reproducer `drmGetDevices2` count/fetch now agree | B1687 |
| FIXED B1687 | HIGH | `config` did not exist at all: no raw config-space blob, so lspci/setpci and every libdrm/libpciaccess fallback path had nothing to read. Now a byte-granular attribute with the reference window rules — 64 bytes for an unprivileged reader (128 for a CardBus bridge), the whole space for `CAP_SYS_ADMIN` in the initial user namespace — and access past the window is a short read, never an error. | `bus::pci_attrs::config::tests::*` (5); `pci::config_space::tests::*` (10) | B1687 |
| FIXED B1687 | MED | The `resource` table emitted one row per *present* BAR, so a function whose BAR0 is unset shifted every later row up and a parser indexing rows by BAR number read the wrong window. Now one fixed row per standard BAR plus the expansion ROM, zero-filled. | `bus::pci_attrs::show::tests::resource_table_is_one_row_per_bar_plus_rom` | B1687 |
| FIXED B1687 | MED | A device's `modalias` carried the driver-side wildcard `sv*sd*` instead of its own subsystem ids, so a modalias-driven match could pick the wrong module. Now emits the captured subsystem identity. | `bus::tests::device_index::pci_device_exposes_indexed_bar_resource_attrs` | B1687 |
| FIXED B1687 | MED | `irq`, `local_cpus`, `local_cpulist`, `numa_node`, `enable`, `power_state`, `dma_mask_bits`, `consistent_dma_mask_bits`, `msi_bus`, `broken_parity_status`, `ari_enabled`, `boot_vga`, `remove`, `rescan` and the bridge bus-number pair were all absent. | OPEN | MED | `resourceN` is a text triple, not the mmap-able BAR window the reference exposes. Unchanged by this lane. | `bus/device.rs` `PCI_RESOURCE_ATTRS` render `resource_body` | unowned |
| OPEN | MED | The config-space accessor is dword-addressed with an 8-bit register offset, so only the 256-byte conventional space is reachable. Extended PCIe config space (and therefore `serial_number`/DSN and the extended capability list) cannot be read; those attributes are absent rather than wrong. Sub-dword writes are read-modify-write on the containing dword, which re-emits neighbouring write-1-to-clear bits. | `pci::ConfigSpaceReader::read32(bdf, offset: u8)`; `pci::config_space::write_bytes` | unowned |
| OPEN | LOW | `dma_mask_bits`/`consistent_dma_mask_bits` report the PCI default 32 for every function because no per-device DMA mask is tracked anywhere in the tree. A driver that would set a 64-bit mask is not represented. | `bus/pci_attrs/show.rs` `DEFAULT_DMA_MASK_BITS` | unowned |
| OPEN | LOW | Bridge windows are not modelled as resources, so a bridge's `resource` table shows the same seven endpoint rows rather than the reference's bridge-window rows. | `bus/pci_attrs/show.rs::resource_table` | unowned |
