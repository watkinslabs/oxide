# B1989 — membarrier SYNC_CORE + RSEQ

| Status | Class | Sev | Issue | Evidence | Owner |
|---|---|---|---|---|---|
| FIXED B1989 | DEFECT | HIGH | `membarrier(2)` refused `PRIVATE_EXPEDITED_SYNC_CORE`, `PRIVATE_EXPEDITED_RSEQ` and both their REGISTER commands with `EINVAL`, and omitted all four from the `MEMBARRIER_CMD_QUERY` mask (0x21f). The in-tree justification claimed parity with a reference built without core-serialization or restartable-sequence support. Both target arches select core-serialization support and enable restartable sequences by default, so the refusal was a divergence recorded as compliance. A JIT that probes SYNC_CORE once and caches `EINVAL` permanently loses its code-patching guarantee. | `crates/kernel/syscalls/src/membarrier/tests.rs::sync_core_and_rseq_commands_are_admitted_not_refused` pins all four admitted and advertised; `..::every_advertised_bit_maps_to_a_distinct_op` walks all 32 command bits and fails if the mask and the command switch ever disagree. QUERY mask is now 0x3ff. | Chris Watkins |
| FIXED B1989 | MISSING | HIGH | No return-to-user core-serialization hook existed, so a thread of the calling mm that was NOT running when a SYNC_CORE barrier was issued could resume user mode with instructions fetched before the code was rewritten. | Per-mm bit + context-switch-tail hook: `crates/kernel/mm-vmm/src/address_space/membarrier.rs::sync_core_before_usermode_tracks_only_sync_core_registration`, `crates/kernel/sched/src/membarrier/arch.rs`, bound in `crates/kernel/sched/src/live/schedule/switch.rs`. x86_64 executes a serializing instruction; aarch64 is a no-op because its user return is already a context synchronization event, matching the reference wiring the hook on one arch and not the other. | Chris Watkins |
| FIXED B1989 | MISSING | MED | The restartable-sequence abort fired only when a thread actually lost the CPU, so a `PRIVATE_EXPEDITED_RSEQ` barrier that preempted nobody would let a critical section straddle it. | `Task::rseq_force_fixup` latch set by the barrier IPI and read-and-cleared unconditionally on both arch IRQ-exit-to-user paths (`arch-irq/src/{lapic,gic}/dispatch.rs`), so the abort is owed whether or not the round preempted the thread and a slice grant does not excuse it. | Chris Watkins |
| FIXED B1989 | COVERAGE | HIGH | `sched::membarrier` was declared `#[cfg(target_os = "oxide-kernel")]` in `sched/src/lib.rs`, so ANY `#[cfg(test)]` block written inside it would have compiled out silently and reported "ok" having built nothing — the phantom-test trap. | Module is now a manifest with ungated `policy` (decision logic) and `arch` (serializing primitive) children and a gated `work` child for the IPI protocol. `cargo test -p sched --lib membarrier` went from 0 to 6 tests; six positive controls (one per rule) were each reinstated, shown RED, and restored GREEN. | Chris Watkins |
| OPEN | COVERAGE | MED | The publish order in the expedited round — round KIND stored Release BEFORE `PENDING` — has no check that can fail. Reversing the two stores lets a target run a plain barrier for a SYNC_CORE round and silently drop the guarantee; nothing hosted or booted would notice. The rest of the protocol is equally unpinned (ACK wait, single-in-flight `OWNER` handoff). Needs a loom model of the sender/target pair, which the repo already uses elsewhere. | `crates/kernel/sched/src/membarrier/work.rs` — `KIND.store(..., Release)` then `PENDING.store(targets, Release)`; `service()` reads KIND only after an Acquire load of `PENDING` saw its own bit. | unowned |
| OPEN | INFRA | LOW | A `make feature-gate-x86` run launched from this worktree produced a log file whose cargo `Checking <crate> (<path>)` lines named ANOTHER lane's worktree interleaved with this one's (51 lines each). The exit status was correct and the real error was in the log, but a reader trusting the paths would conclude the gate had type-checked the wrong tree. Same class as the existing "trust the exit status, never a log found by timestamp" rule, but here the log was freshly created by this lane's own redirect. | Two concurrent `make feature-gate-*` runs on a shared box; `grep -c 'kernel-B1989'` and `grep -c 'kernel-B19[0-8][0-9]/'` both returned ~50 on the same file. | unowned |
