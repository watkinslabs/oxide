# B1717 — NetworkManager device list empty

| Status | Issue | Evidence |
|---|---|---|
| FIXED (this PR) | AF_NETLINK `recvmsg` never reported `SCM_CREDENTIALS` except on `NETLINK_KOBJECT_UEVENT`, where it reported them unconditionally. `SO_PASSCRED` was accepted-and-dropped on netlink sockets. A client that sets `SO_PASSCRED` and discards uncredentialed messages therefore saw an empty link cache. | In-guest NM trace: 18× `platform-linux: rtnl: recvmsg: received message without credentials` during `populate platform cache`, then ACK timeouts; zero `new Ethernet device` lines; `nmcli -t device status` empty while `ip -o link` lists `lo` and `eth0` and `udev-add[eth0,2]` succeeded. Tests: `netlink::creds::tests::*`, `netlink::netlink_tests::creds::*`. |
| OPEN | `SO_PASSSEC`/`SCM_SECURITY` and `SO_PASSPIDFD`/`SCM_PIDFD` are not implemented on any socket family, netlink included. Linux `scm_recv` emits both alongside `SCM_CREDENTIALS`. No consumer observed failing on it yet. | `grep -rn "SCM_SECURITY\|SCM_PIDFD" crates/` returns nothing. |
| OPEN | A net interface has no `device` or `driver` symlink: `/sys/class/net/<if>` always projects under `/sys/devices/virtual/net/`, even for the virtio-net NIC whose transport kobject exists at `/sys/devices/pci0000:00/<bdf>/virtioN`. udev's `path_id` and `net_id` builtins therefore cannot compute `ID_NET_NAME_PATH`, and the interface keeps the kernel name `eth0` instead of a predictable one. Not the cause of the empty NM device list. | `crates/kernel/sysfs/src/net_class.rs` `NetIfaceOps::lookup` has no `device`/`driver` case; the netdev registry (`net::sock::stack().ifaces`) and the `drv::Device` bus registry are disjoint. |
| NOT A GAP — deliberate, pinned | `/sys/subsystem/` is absent, and must stay absent. It is a proposed classification unification that was never implemented: nothing creates it, and by contract its presence is the promise that it holds EVERY bus, class and block device in one flat `<name>/devices/` layout, on which a conforming enumerator stops scanning `/sys/bus`, `/sys/class` and `/sys/block` altogether. Publishing a partial one would SUPPRESS the enumeration that works today — udev would see less, not more. The per-device `subsystem` symlink, which is the thing that really exists, we already emit. | Pinned by `sysfs::root_tests::the_sysfs_root_publishes_no_subsystem_unification_directory`; positive control — `register_dir("/sys/subsystem")` turns it RED. Existing symlink coverage: `sysfs::net_tests::net_iface_dir_exposes_subsystem_symlink`. |
| OPEN (negative result) | udev and sysfs are NOT implicated in the empty NM device list. `/run/udev/data/n2` is written (84 bytes) and NM's own `udev-add[eth0,2]`/`udev-add[lo,1]` fire. Do not re-investigate that direction. | Boot log + NM trace, 2026-08-02. |
| OPEN | `/run/udev/data/n1` (loopback) is a stale zero-byte file dated 1970 shipped in the rootfs image; udev never rewrites it. Cosmetic, but it makes "does lo have a udev record" unanswerable by listing alone. | `ls -l /run/udev/data/` in guest. |
