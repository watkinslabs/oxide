# C270 — the interrupt stack gets a measured budget

| FIXED (this PR) | COVERAGE | high | **The interrupt path was invisible to the stack-depth gate, which is why the `#DF` was found by dying rather than by a check.** The walker follows direct call edges only, and every hardware interrupt handler in this kernel is reached through a registered function pointer — the MSI vector table, the x86 line-handler table, the nine softirq slots, the NAPI poll list, the tick-poll hook and the exit-to-user hook. So the receive path measured **8 bytes** deep and `drv_serial::deliver` 32, and the gate's own docstring recorded the gap rather than closing it ("INTERRUPTS AND EXCEPTION ENTRY are not modelled"). The target sets are finite and enumerable — each table has a handful of registration sites, all in this tree — so they are now named in `tools/irq-edges-<arch>.tsv` and merged into the call graph before the walk. With 23 edges resolved on x86_64 the interrupt path reports its real depth for the first time: **8704 B of the 16384 B interrupt stack**. | `make irq-gate-x86` PASS at a 12000 B ceiling, printing 8704 (`oxide_irq_exit_to_user`) and 8432 (`oxide_irq_dispatch`). Positive control: `--irq-fail 8000` exits **1** naming both roots. Without the map the same roots report 7600/7872, and `rx_isr_msi` reports 8. | C270 |
| FIXED (this PR) | COVERAGE | high | **The hardirq stack had no budget of its own.** It is a different 16384 B from the task stack with a different worst case: the entry asm deliberately does not re-switch when an interrupt arrives while already on it, and the softirq drain runs with interrupts unmasked, so a second entry lands on top of whatever the drain has already spent. A single ceiling shared with task stacks cannot express that. `--irq-roots` / `--irq-fail` add a second domain rooted at the two functions the entry asm calls after switching SP, with a 12000 B ceiling — the 4 KiB below the stack size is not slack, it is the nested interrupt's stack. | New `irq-gate` target, in `make ci` and in the pre-push hook alongside `frame-gate`/`stack-gate`. | C270 |
| FIXED (this PR) | COVERAGE | med | **The gate's pass/fail decision had no test.** `--self-test` covered the accounting — prologue summation, the arch return-address difference, recursion, indirect flagging, the blocking tail, allowlist identity — and stopped short of the layer that turns a number into an exit code, which is the layer that actually merges or blocks a defect. Extracted as `verdict()` and tested with a positive control per branch, each asserting the intended verdict fires AND the others stay empty so a rule that fires on everything cannot pass. The case that matters: a path one byte deeper than its recorded budget must be `worse`; a ratchet written `>=` instead of `>` lets a path grow without limit one byte at a time with every run green. | Positive control run: relaxing that comparison makes `--self-test` fail with `AssertionError: []`; restoring it passes. | C270 |
| OPEN | DEFECT | high | **Resolving the dispatch edges exposed 13 syscall paths at 13.1–14.2 KB of the 16384 B task stack, previously invisible.** They are not regressions — the walker simply could not see them past the indirect calls, and they are still not visible to the default `stack-gate`, which is why the map is carried by `irq-gate` and not yet folded into `stack-gate`. Deepest: `oxide_syscall_entry` 14248, `oxide_syscall_dispatch` 14064, `sys_sendmmsg` 13760, `sys_io_submit` 13600, `sys_io_uring_enter` 13568, `sys_recvmmsg` 13392, `sys_readv` 13280, `sys_recvmsg` 13200, `sys_pwritev2` 13184, `recvmmsg Batch::receive` 13168, `sys_read` 13168, `sys_recvfrom` 13152, `sys_writev` 13104. A page fault taken in one of these runs on the same task stack, so ~2 KB is the whole margin.
