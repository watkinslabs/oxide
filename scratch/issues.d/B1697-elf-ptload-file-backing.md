# B1697 — ELF PT_LOAD file backing

| Status | Sev | Issue | Evidence | Owner |
|---|---|---|---|---|
| FIXED B1697 | high | The ELF loader mapped program segments as kernel-owned byte ranges rather than as file-backed mappings, so a program's text and data classified as "private with nothing behind it" and were skipped by every core-dump filter bit. `place_image` now maps the part of each `PT_LOAD` that is a mapping of its file as `VmaBacking::File`, so `describe_vma` reports `file_backed`, the header-page rule and the file-backed private class apply, and `NT_FILE` can name the mapping. | `crates/kernel/exec/src/tests_file_backing.rs::text_is_a_mapping_of_the_file_it_was_loaded_from`; positive control: forcing the file backing off turns 4 of those tests RED. | — |
| OPEN | med | A `PT_LOAD` whose memory size exceeds its file size still gives up its boundary page: that page is part file content and part `.bss`, which a mapping of the file cannot serve, so it stays kernel-owned and classifies as private-with-nothing-behind-it. The reference kernel keeps the page inside the file-backed mapping and zeroes the tail through the new address space, which this loader cannot do because it runs before that address space is activated. The page is only dumped once a private file mapping acquires an `anon_vma` on first write, which this kernel does not yet do either. | `crates/kernel/exec/src/tests_file_backing.rs::a_data_segment_is_the_file_up_to_its_boundary_page`; `layout::split`. | — |
| OPEN | med | A position-independent image with no interpreter keeps the kernel-owned backing for all of its segments: the loader applies its `R_*_RELATIVE` entries before it runs, so those bytes differ from the file and cannot be a mapping of it. The reference kernel applies none of them — such an image relocates itself from its own entry point — so the durable fix is to stop pre-applying and confirm the userspace images self-relocate. | `layout::relocs_precede_file_backing`; `only_a_biased_dyn_image_the_loader_relocates_loses_its_file_backing`. | — |
| OPEN | low | A private file mapping never acquires an `anon_vma`, so a page the process wrote is not reported as "has pages of its own" and the anonymous-private filter bit does not reach it. Under the default filter this loses a crashed program's modified `.data` even now that the mapping is file-backed. | `Vma::new_with_may` allocates an `anon_vma` only for `VmaBacking::Anonymous`; `coredump::filter::describe_vma`'s `anon_vma` field. | — |
