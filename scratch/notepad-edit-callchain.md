# Notepad EDIT startup / font / paint call-chain inventory

Static review: 2026-09-06. Branch `current` below = `D1550-notepad-masterplan`.
Reference identity: actual source-built Wine **10.20**, verified version and build srcdir agreement; not the separate 11.16 reference checkout. Reviewed implementation functions, wrapper/export forwarding, generated x64 ordinal signatures, current raw admission, dispatch and canonical owners. No implementation, build, or boot performed for this inventory.

Scope: empty Notepad creation through EDIT WM_NCCREATE/WM_CREATE, explicit WM_SETFONT, first WM_PAINT, focus and first nonempty text shaping. Printing, file loading, dialogs, all status-bar internals and general complex-script completeness are not claimed audited. Conditional branches are distinguished from unconditional calls; this is not evidence that a particular boot reached them.

## Execution order

1. Notepad main-window WM_CREATE calls GetClientRect, then creates a visible multiline EDIT with WS_EX_CLIENTEDGE, WS_VSCROLL, ES_AUTOVSCROLL and ES_NOHIDESEL; horizontal scrolling depends on the wrap setting.
2. Every EditWndProc_common entry loads EDITSTATE from GetWindowLongPtrW(hwnd,0). WM_NCCREATE allocates EDITSTATE and stores it through SetWindowLongPtrW(hwnd,0,pointer). Missing state redirects later messages to default handling; a bogus nonzero pointer is dereferenced by EDIT_LockBuffer.
3. EDIT_WM_Create invokes EDIT_WM_SetFont with font=0, resets format geometry and updates scroll info. Successful EDIT_WM_Create returns 1; WM_NCCREATE returns TRUE. Current `nt_window/create_lifecycle.rs::after_create` correctly rejects only -1; this is not a missing return-policy fix.
4. Back in Notepad WM_CREATE: SetWindowSubclass, CreateFontIndirectW, SendMessageW(WM_SETFONT,font,FALSE), EM_LIMITTEXT, then status-bar creation. Subclass installation precedes explicit font creation.
5. EDIT_WM_SetFont acquires its DC, selects the requested font when nonzero, reads TEXTMETRICW, derives margins, restores the previous font and releases the DC; resets its format rectangle; rebuilds multiline line definitions; updates IME composition font. Redraw is FALSE during Notepad startup, not proof that no initial paint follows visibility.
6. ShowWindow followed by UpdateWindow requests synchronous redraw of the main window and children. EDIT_WM_Paint gets a paint DC, requests parent control colors, intersects clipping, queries clip bounds, fills background, selects its font, visits visible lines, restores font and ends paint.
7. Nonempty lines invoke ScriptStringAnalyse with SSA_LINK/FALLBACK/GLYPHS/TAB. Successful analysis paints via ScriptStringOut → SS_ItemOut → ScriptTextOut → ExtTextOutW with glyph/paired-displacement semantics. Empty lines skip analysis. Unicode direct output is not the sole normal EDIT renderer.

## Conditional paths and false priorities

### Message-call correction and separate mandatory selectors

- KI-0393 FIX CANDIDATE: final source read confirms raw_callback::message_call uses `nt_message_call_abi::tail(args.a5, stack_argument)`: selector is logical argument 5, ANSI is stack argument 6. Previous ANSI-as-selector / nonexistent argument 7 access is no longer present. This inventory did not run its tests or target gates.
- **SendMessageW uses selector 0x02b1, not GetDispatchParams.** Notepad's WM_SETFONT and EM_LIMITTEXT calls, plus EDIT's parent notifications/control-color requests, take this route. Wrapper initializes only params.hwnd=0, calls NtUserMessageCall with an otherwise uninitialized win_proc_params, then invokes dispatch_send_message if params.hwnd is nonzero. Unsupported selector leaves hwnd zero, so the local EDIT procedure is never called.
- Same-thread fast path requires destination thread match, no call-WndProc hooks, and allowed recursion depth. It populates canonical HWND/WNDPROC, message arguments, ANSI source/destination, SENDMESSAGE character mapping and DPI context; it does **not** call the procedure in kernel and then request a second client call. send_window_message returns its initialized result (zero on this fast path); USER32 supplies the actual WndProc LRESULT after local dispatch. Cross-thread/hooked/broadcast sends require their real message semantics, not unconditional same-thread treatment.
- **GetDispatchParams selector 0x3001 is separate.** Ordinary DispatchMessageW calls it and treats return as BOOL before dispatch_win_proc_params. WM_PAINT and WM_SYSTIMER instead go through NtUserDispatchMessage; WM_TIMER with callback has its own handling. 0x3001 validates same-thread/window eligibility, fills the whole record with DISPATCHMESSAGE mapping, and returns FALSE on failure. A nonzero STATUS_NOT_IMPLEMENTED here lets USER32 consume an uninitialized record.
- Current raw and descriptor NtUserMessageCall implementations still accept only DEF_WINDOW_PROC and CALL_WINDOW_PROC selectors. KI-0393 fixes argument decoding, not these absent selectors. Existing initialize_window_proc_params reads a caller-provided func and uses CALLWINDOWPROC mapping; correct for CallWindowProc, **not reusable unchanged** for SendMessage/GetDispatchParams, whose procedure must be resolved from canonical HWND and whose caller does not initialize func.
- Required main-owned integration: separate same-thread parameter preparation from explicit-procedure initialization; enforce canonical owner/thread/Unicode metadata and correct mapping; use the appropriate BOOL versus LRESULT domain; test actual wrapper-shaped input with only hwnd initialized for SendMessage and no initialized input record for GetDispatchParams. Never read the procedure from those input buffers. No new raw ordinal is needed: both selectors use the existing seven-argument 0x14b5 service.

- Notepad uses WS_EX_CLIENTEDGE, so EDIT_WM_NCCreate clears its internal WS_BORDER flag. The four explicit border PatBlt calls inside EDIT_WM_Paint are therefore not the ordinary Notepad branch; outer nonclient edge painting is separate.
- Empty multiline lines skip ScriptStringAnalyse. A white empty window cannot validate the first typed-token path. Failed analysis sets ssa=NULL; EDIT fallback painting is not a supported substitute for implementing shaping and can have no useful nonselected multiline count in this path.
- CJK ABC-margin calls occur only after charset/font-signature classification. GetTextCharsetInfo itself is still reached for the default Unicode TrueType margins; do not mark the entire chain CJK-only.
- GdiGetCodePage reads shared DC_ATTR.font_code_page, not a new syscall. Verify initialization and selected-font updates in client publication; adding an ordinal for this PE helper would be wrong.
- IME composition operations are reached by EDIT_WM_SetFont: ImmGetContext directly calls NtUserCallHwnd **0x1332** / GetWindowInputContext; ImmSetCompositionFontW first calls NtUserQueryInputContext **0x14dd** / ThreadId and returns FALSE unless it matches the current thread, then locks/updates the real context. Both raw routes are absent at inspection. EDIT ignores the BOOL; no-context behavior is not proven a fatal startup blocker. ImmReleaseContext returns TRUE locally, so it requires no invented release syscall. A valid context must retain correct ownership and notification semantics.
- Status-bar creation is explicit in Notepad startup but its complete comctl32 call chain was not folded into EDIT semantics. Menu/icon/cursor speculation is not evidence for this inventory.

## Return-domain hazard

`raw_args::decode_x64` returns Unclaimed for ordinals absent from RAW_CALLS; `dispatch_raw_linux` returns None. Current `dispatch/core.rs::dispatch_routed_syscall` then tries normal routes and ends with Linux -ENOSYS for unmatched numbers. These are Windows ABI consumers: pointer NULL, BOOL FALSE, DEFAULT_CHARSET, region ERROR and GDI_ERROR are different failure domains. A blanket negative status can look like a valid pointer, positive size or successful glyph query. Required service implementation must supply real outputs and exact Windows return semantics; changing generic failure values alone does not implement these services.
