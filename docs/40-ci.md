PR-time CI is the hosted merge wall. Local pre-push and post-merge gates cover the KVM-only boot path. No soak gating or duration-based exit criterion.

## 1 Enforced invariants

1. `.github/workflows/pr.yml` runs on every pull request targeting `main`; `workflow_dispatch` is the manual replay path. No `push` trigger duplicates the pull-request run.
2. `main` branch protection requires every unconditional context in §2 with strict up-to-date-branch evaluation.
3. The pinned Rust toolchain, `rust-src` and bundled LLVM tools build both kernel targets on `ubuntu-latest`; ARM is cross-compiled, not claimed as a native runner.
4. Boot smoke stays local: KVM boots both architectures before boot-visible pushes and after every merge per `CLAUDE.md`.
5. Full spec-lint and workspace tests remain opt-in while their recorded baselines are red; skipped jobs are not required checks.

## 2 Automatic PR checks

These eight contexts run on every PR and are required by `main` protection.

| Job | Cmd |
|---|---|
| `lint-ratchet` | spec-lint findings may not grow per `(crate, rule)` against `tools/spec-lint/baseline.tsv` |
| `warnings --hosted` | warning-gate controls, workspace build, isolated host crate checks and isolated test-target builds |
| `build kernel x86_64 (default)` | x86_64 dev-profile compile check, default features |
| `build kernel x86_64 (debug-all)` | x86_64 dev-profile compile check, all routine debug features |
| `build kernel aarch64 (default)` | aarch64 dev-profile cross-compile check, default features |
| `build kernel aarch64 (debug-all)` | aarch64 dev-profile cross-compile check, all routine debug features |
| `stack gates x86_64` | release ELF frame-size, static task-stack depth and hard-IRQ stack-depth gates |
| `stack gates aarch64` | release ELF frame-size, static task-stack depth and hard-IRQ stack-depth gates |

`spec-lint` and `test --hosted` are manual opt-ins controlled by `OXIDE_RUN_SPEC_LINT` and `OXIDE_RUN_HOSTED_TESTS`. Missing miri, loom, clippy, dependency, coverage, benchmark and acceptance automation remains live in `scratch/known_issues.md`; it is not implied by this table.

## 3 Release tag CI

No release workflow exists yet. Required release checks remain open infrastructure work:
1. PR-time CI green on the tagged commit, both arches.
2. All `43§2` minimum acceptance scenarios pass on the tag.
3. Kernel-completeness audit uses a live canonical source; the deleted `docs/kernel-audit.md` cannot gate a release.

Artifact: `(commit, arch, sha256s of kernel + rootfs, acceptance-binary list with exit codes)`.

## 4 Bench history

No benchmark workflow or `bench-history/main` store exists yet. The required design is per-commit median+p99 cycles, pruned to 90 days plus version tags.

`tools/perfrunner/` cycle-accurate timing (`rdtsc`/`cntvct`), 1000 iters/op, 5 trials.

PR bench job: rerun, compare last `main` commit; fail >5% p99 regress on any `04§1` hot path.

## 5 Docker image (build env)

No `Dockerfile.build` or image workflow exists yet. PR jobs currently install the pinned Rust toolchain directly on `ubuntu-latest`.

### 5.1 `Dockerfile.build`

Base: `debian:trixie@sha256:<digest>` (digest-pinned).
Layers:
- nightly rustc per `rust-toolchain.toml` + `rust-src` + `rustfmt` + `clippy` + `miri` + `llvm-tools-preview`.
- `qemu-system-{x86_64,aarch64}`.
- EDK2/OVMF firmware (x86_64) + `qemu-efi-aarch64`.
- `mtools`, `sgdisk`, `zstd`, `cpio` (image building).
- `cargo-deny`, `cargo-tarpaulin`, `cargo-fuzz`.
- `git`, `curl`, `make`.

Multi-stage to keep final image lean.

| File | Trigger | Action |
|---|---|---|

## 7 Runners

- PR-time: GHA hosted `ubuntu-latest`; x86_64 builds natively and aarch64 cross-compiles.
- KVM boot smoke: local development host, x86_64 and aarch64 QEMU in parallel when uncontended.

## 8 Test contract

- PR adding `static mut FOO`: build fails (`07§5`).
- PR adding a new lint finding over the ratchet baseline fails.
- PR adding a compiler warning fails the hosted or kernel build that reaches it.
- PR growing a linked release frame or static task-stack path over its budget fails on the affected architecture.

## 9 Failure modes

- A required context that never starts blocks merge; verify the workflow trigger and exact context spelling before changing protection.
- Hosted-runner exhaustion leaves the PR blocked; replay with `workflow_dispatch` after capacity returns.

## 10 Debug

Use the Actions run for the exact PR head SHA. Boot logs are local gate artifacts, not hosted CI artifacts.
